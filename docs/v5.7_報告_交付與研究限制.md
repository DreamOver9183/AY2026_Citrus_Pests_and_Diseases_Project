## 2. ⚠ 報告這組數字時必須同時說的話

**`test mAP50 0.861` 不可以拿去跟 v11.5 的 `0.810` 相比，更不可以說成「進步了 0.05」。**

v5.7 只改了一件事：`Thrips_Damage` 的框定義從「一塊食痕一個框」改成「一張葉子一個框」，
框的中位面積從 11.30% 變成 15.40%（**1.36 倍**）。
AP50 的判定是「預測框與標註框的 IoU ≥ 0.5 即命中」——**框愈大愈容易達標**。

| | v11.5 @ v5.6 | **v5.7（本次交付）** | 差 |
| --- | ---: | ---: | ---: |
| 九類 test mAP50 | 0.80959 | 0.86118 | +0.0516 |
| 其中 `Thrips_Damage` 一類貢獻 | — | — | **+0.0438** |
| **八類平均 AP50（標註未變動）** | **0.85268** | **0.85082** | **−0.0019** |

那八類的來源影像與標註在兩版之間**逐位元相同**，是唯一可以直接比較的東西，
而它**沒有變化**（−0.002，遠小於 run 間全距 0.021）。

**正確的講法**：
> 「v5.7 在新的標註約定下，九類 test mAP50 為 0.861。
> 這個數字與 v5.6 以前不可比，因為 `Thrips_Damage` 換了框定義；
> 在標註未變動的八類上，v5.7 與 v11.5 的表現相同。」

跨版本的趨勢圖、表格一律用**八類平均**，或明確分成「v5.6 以前」與「v5.7 以後」兩段。

## 3. 研究限制

### 3.1 標註

1. **`Thrips_Damage` 的類內一致性實測是 0.80–0.83，不是 0.899。**
   0.899 是「兩個人當場照新約定重畫同樣 20 張」的一致性（工作包 A 第二輪）；
   實際重標全類 208 張時，其中 **152 張沿用了歷史框**——它們本來就只有一個框、
   已符合新約定，重畫換不到東西。以工作包 A 的 20 張為基準實測，這批標註對
   第一位標註者是 0.832、對第二位是 0.800。
   分開看，沒動過的 12 張是 0.837、改過的 8 張是 0.784，**沒動過的並沒有比較差**。
   殘餘差距的兩個成因都已定位：細長框的 IoU 天生吃虧、以及「多淡還算受害」沒有定義
   （見 [工作包 A 結果](v5.6_結果_工作包A標註一致性.md) §9.3）。

2. **`Scale_Insect` 的框一致性從未量過**，而它是 pooled AP50 最低的一類（0.632）。
   它的 valid − test 落差在**完全相同的資料**上三輪量到 **0.040 / 0.174 / 0.084**——
   同一份資料、同一份訓練碼，落差自己在跳。這正是 `Thrips_Damage` 當年被抓出來的徵狀。
   **這是 future work 的第一項。**

3. **其餘七類的標註品質同樣沒有量過。** 本專案只對 `Thrips_Damage` 做過雙人一致性測試。

### 3.2 評估

4. **評估集規模**：valid 401 / test 401 張。逐類 ±2SE 雖然全部 ≤ 0.10，
   但那是**逐類**的下限；`Scale_Insect` 只有 valid 35 / test 35 張，
   小到 valid/test 落差本身就不穩定（見 3.2 上一點）。

5. **per-class 的雜訊地板是 ±0.04。** v11 實測：資料完全沒動的五個類別在重跑之間
   移動了 −0.044 ～ +0.015；v5.7 的兩臂又獨立確認一次（七個未變動類別 −0.007 ～ +0.021，
   單一 split 上可達 ±0.05）。**小於這個幅度的 per-class 差異一律不解讀。**
   整體 mAP50 的 run 間全距是 0.021。

6. **valid 與 test 併計的前提是 `patience=0` ＋ 固定輪數。**
   任何改用早停或以 valid 挑權重的做法，都會讓 valid 失去併計資格。

### 3.3 資料

7. **本專案不曾新拍任何照片。** v11 計畫書算出要達到 A 級目標需新增 1,305 張、
   B 級需 353 張；v5.6 證明**評估精度**的目標不需要新照片就能達成，
   但**模型精度**至今沒有任何一條不需要新照片的路走通。

8. **外部資料只試過一批，而且無效。** ext 臂的 124 張公開潛葉蛾影像
   （實際只有約 20–25 片不同的葉，大量連拍）換到 CLM AP50 +0.021，
   與同一輪裡完全沒加資料的類別移動幅度相同。**這是「這批照片無效」，
   不是「外部資料普遍無效」**——成因是域差距（離體葉放白紙 vs 田間照）。
   另已查遍公開資料集：**找不到附框的柑橘潛葉蛾／薊馬偵測資料集**。

9. **`Aphid` 與 `Thrips` 的來源含圖鑑／微距特寫**，與田間部署域不同。
   v5r 已把 Thrips 的葉害子域拆出來，但蟲體子域的域混用仍在。

### 3.4 部署

10. **所有部署結論只成立於一台裝置**（Snapdragon 662 / SM6115）。無第二台測試機。

11. **即時辨識不採用**，依 v12.2 登記的門檻（≤ 40 ms **且** test mAP50 ≥ 0.764
    **且** 逐類跌幅 ≤ 0.10）：五個候選延遲全部過線、**精度全部未過**（最高 0.709）。
    延遲與精度沒有重疊的解析度——fp32 要降到 224 才進得了 40 ms，
    但精度在 288 以下就斷崖式下滑。

12. **`Benchmark/Model/` 底下的 22 個 TFLite 匯出是從 v11.5 的權重產生的**，
    不是本次交付的 v5.7。**延遲不受影響**（架構與尺寸完全相同），
    但精度數字屬於 v11.5。App 實際要出的那一顆需要重新匯出與重評。

> **注意：v5.7 的 0.861 不構成重開即時辨識的理由。**
> v12.2 的門檻 0.764 是從 v5.6 標註下的 `fp32@320` 0.785 推出來的，
> 拿 v5.7 標註的數字去對它，就是 §2 講的那個錯誤。
> 要誠實地重開，門檻必須在 v5.7 標註下重新推導；
> 而標註未變動的八類沒有變化，代表差距會原封不動地平移
> （第一階段最好的 0.709 離門檻差 0.055，兩邊同時上移約 0.05，差距不變）。
> **S2 的結論維持。**

### 3.5 方法

13. **本專案的所有結論建立在 `ultralytics==8.4.121`。** 版本釘死是刻意的——
    v9 之後的所有數字都在這個版本上取得。

14. **v8 與 v5/v5r 的歷史數字已作廢**：以感知雜湊查出 v5r 的 valid 有 44.5%、
    test 有 47.5% 落在 v5 的 train 裡，**不存在對 v8 乾淨的評估集**。
    v5.5 起才有零洩漏的切分。
