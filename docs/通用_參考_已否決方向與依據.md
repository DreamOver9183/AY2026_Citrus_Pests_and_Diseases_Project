### 1.2 模型容量（v12s，2026-09-10）

| | |
| --- | --- |
| 改動 | 只改 scale：`n` → `s`（**3.84 倍參數**），其餘一個字不動 |

### 1.3 `close_mosaic`

**刻意不動它**——要驗證它的去留應該當成獨立一臂測，

## 2. 部署端：即時辨識不採用（v12.2，2026-09-11）

### 2.1 功能採用門檻（開跑前登記）

過線要**同時**滿足三條：延遲 ≤ 40 ms、test mAP50 ≥ 0.764、逐類跌幅 ≤ 0.10。

第一階段五個登記組合：**延遲全部過線（28.5–38.0 ms）、精度全部未過（最高 0.709）**
→ **S2 觸發，不採用即時辨識，App 只做拍照辨識。**

根因是**延遲與精度沒有重疊的解析度**：fp32 要降到 224 才進得了 40 ms，
但精度在 288 以下就斷崖式下滑。這不是調參數能繞過的。

### 2.2 用實測擬合的延遲模型先算上限，算不到就不跑

QAT、NCNN、拿掉 P2 頭三條路都在**開跑前**用延遲模型算過上限而直接關掉，
沒有浪費量測時間。唯一上限仍過線的是 **QAT@288**（延遲 38.0 ms、精度上限 0.768、
餘裕僅 0.004），但 QAT 不在 `ultralytics==8.4.121` 裡，且成功機率低，**不在預算內**。

### 2.3 匯出參數（v12.1，22 組精度 × 18 組延遲的完整掃描）

| 已關閉 | 原因 |
| --- | --- |
| GPU delegate | `end2end` 的算子擋住，**反而更慢** |
| NNAPI | 同上 |
| `w8a16` | 量測失敗且無下界，已結案 |
| 靜態 INT8 | **會關掉 `end2end`**，變成另一個體系的模型 |
| `w8a32` | **省體積不省時間** |

**有效槓桿只有 `imgsz`**（640 → 320 快 4.11 倍、只掉 0.032）。
最佳可用組合是 `fp32@320` = 64.8 ms / 15.4 FPS / mAP50 0.785。
**平台 1（Snapdragon 662）達不到 30 FPS**，差 6.8 倍。

### 2.4 三個文件沒寫清楚的陷阱

| 參數 | 實際行為 |
| --- | --- |
| `end2end` | 官方文件沒寫，但可用；**靜態 INT8 會把它關掉** |
| `max_det` | 不是「上限」，它把 TopK 的 k **烘進模型** |
| `fraction` | 不是隨機抽樣，是**排序後取前綴**——當驗證子集會系統性偏誤 |

## 3. 資料端

### 3.1 外部影像補 CLM（ext 臂，2026-09-13）

| | |
| --- | --- |
| 做法 | 124 張公開資料集的潛葉蛾影像進 train，**配額中性**（佔用 CLM 既有增強配額） |
| 判準（開跑前寫死） | ext − base 的 CLM AP50 **> 0.04** |
| 實得 | **+0.021** |
| 裁決 | **✗ 未通過** |

**關鍵證據不是 +0.021 這個數字，是對照組**：兩臂之間只有 CLM 的資料不同，
其餘八類逐位元相同，而同一輪裡完全沒加資料的 `Oily_Spot` 動了 **+0.0211**，
七個未變動類別的移動範圍是 −0.007 ～ +0.021。
**加了 124 張的那一類，移動幅度跟什麼都沒加的一模一樣。**

成因：那 150 張裡有大量連拍，**實際只有約 20–25 片不同的葉**；
而且與田間照**域差距很大**（v11.5 在那批照片只認得出 5%）。
**這是「這批照片無效」，不是「外部資料普遍無效」**——但除非拿得到同域資料，不要再走。

> 另已查遍公開資料集：**全世界找不到附框的柑橘潛葉蛾／薊馬偵測資料集。**

### 3.2 影像剪接合成（copy-paste，C 工作包）

把 CLM 食痕以 `cv2.seamlessClone` 貼到健康株影像上。
**已取消**——合成品質不足以通過人工視覺驗收，貼上去的痕跡與真實食痕的紋理對不上。

### 3.3 圖片生成

同樣否決。理由與 3.2 相同，而且生成影像的標註框位置無法驗證。

### 3.4 用色彩門檻自動找食痕

想用色彩門檻自動產生 B 包的框。**與人眼標註的中位 IoU 只有 0.42**，
而且會大面積誤框（葉緣反光、枯黃區都被吃進去）。**已否決，別再試。**

### 3.5 用現有模型預標外部影像

v11.5 在 B 包的 150 張裡**只認出 7 張（5%）**有潛葉蛾。
域差距太大，模型當不了預標器——B 包最後是由 AI 代理看圖粗標 ＋ 使用者單人審。

## 4. 標註端

### 4.1 `Thrips_Damage` 的舊分框約定（工作包 A 第一輪，2026-09-12）

| | |
| --- | --- |
| 約定 | 「兩塊食痕中間夾的健康葉肉，比較小的那一塊還寬 → 分兩個框」 |
| 判準（2026-08 登記） | 兩人各標 20 張，中位 IoU **≥ 0.85** |
| 實得 | **0.746** |
| 裁決 | **✗ 未通過** |

**注意：這不是「規則沒寫清楚」。** 那條分框規則本來就是量化的，
寫到那個程度兩人在 5/20 張上還是分不一樣。
診斷指出失效**集中在「分成幾個框」而不是邊界**（框數相同的 15 張已有 0.872）。

### 4.2 刪除 `Thrips_Damage`（v11 §7 的中止條件）

第一輪未過之後，v11 §7 的登記動作是「刪掉該類別」。**沒有執行**，理由是
它引用的 [P3 §2.2](archive/v9_說明_P3定位精度改善與測試流程.md) 對這個子域的原話是
**「不要刪」**——它是唯一符合田間部署域的 Thrips 訊號，而且刪掉**不會讓數字變好**
（實測 valid −0.002 / test −0.012）。**刪類別換不到指標**，換掉的只有部署能力。

改走第三條：把約定改成「一張葉子一個框」、**只重測一次**，
規則與期限在重測之前 commit（`2914698`，23:44:39；重測匯出 23:51/23:53）。
第二輪 **0.899 通過** → 全類 208 張重標，進 v5.7。

## 5. 三個會靜默毀掉結果的坑（不是「否決」，是「踩過」）

這三個的共通點是：**不會報錯，而且既有的檢查全部照樣綠燈。**

| 坑 | 症狀 | 防線 |
| --- | --- | --- |
| **EXIF 旋轉標記** | 標註軟體不一定照標記轉，訓練端會轉 → 框差 90°，而格式檢查抓不到。B 包 150 張有 118 張、A 包 20 張有 5 張 | 工作包影像一律先轉正；`prelabel_assist.py` 看到旋轉標記就停 |
| **LabelImg 覆寫 `classes.txt`** | 用它內建的清單（dog／person／cat…）覆寫，連帶把框寫成別的類別編號（實測 `001.txt` 變成類別 15） | `check_annotation_return.py` 的類別檢查；`prelabel_assist.py diff` 同樣檢查；A/B 兩包的說明書與檢查表都寫了 |
| **`cv2.imread` 在中文路徑回傳 `None`** | 不丟例外。呼叫端把 `None` 當成「這張跳過」→ **整批增強產出 0 張**，建置仍然「成功」結束，**而八道 Gate 照樣全綠**（它們檢查的是比例，不是絕對張數） | 一律用 `build_dataset_v5r.py` 的 `imread_any()` / `imwrite_any()`；配額不為 0 卻產出 0 張就當場中止 |

還有一個**不是坑但值得記住**的：`ultralytics==8.4.121` 的 `resume=True`
會**靜默換成 COCO 權重**（辨識法：`Transferred 902/902`）。已修並實戰驗證。

## 6. 一頁總結

| 方向 | 試了幾種 | 結果 |
| --- | ---: | --- |
| 模型架構／損失 | 5 | 全部未過 2σ，四種顯著變差 |
| 模型容量 | 2（`s`、連帶否決 `m`） | +0.003 / 門檻 0.03，未過 |
| 訓練協定 | 1（`patience=0` + `last.pt`） | **有效**——但修的是「報得出來的精度」，不是模型 |
| 部署匯出參數 | 22 組 | 有效槓桿只有 `imgsz`；即時辨識不採用 |
| 資料：合成／生成 | 2 | 品質不足，取消 |
| 資料：外部影像 | 1 | +0.021 / 門檻 0.04，未過 |
| 資料：自動標註 | 2（色彩門檻、模型預標） | IoU 0.42 / 只認得出 5%，否決 |
| 標註：重標 | 1 | **有效**——但修的是一個假問題，模型沒變好 |

**結論**：在不新拍照片的前提下，工程手段已經用盡。
兩個「有效」的都是**讓數字變得可信**，沒有一個讓**模型變好**。

剩下有依據的下一步只有兩件：
1. 量 `Scale_Insect` 的框一致性（它接手成為最弱的一類，且 valid/test 落差在同一份資料上會從 0.04 跳到 0.17）
2. 補拍同域照片（v11 計畫書算過：B 級目標需 353 張）
