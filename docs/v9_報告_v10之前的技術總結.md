## 2. 資料集：v5 → v5r 的標註重整，是唯一有效的手段

### 2.1 那條相關係數

八個類別的「標註邊長極差 p99/p10」與 v8 的 per-class AP，Spearman **ρ = −0.976**。

**框大不是問題，同一類混用兩種尺度才是問題。** 這條關係是整個專案後續所有
資料端決策的依據，到 v5.6 仍在用（v5.6 把 CLM 的極差從 9.9x 收到 9.0x，
就是依這條關係預期 AP 會小幅上升）。

### 2.2 Thrips：兩個互不重疊的影像域被塞進同一類

| 子域 | 內容 | 尺度 |
| --- | --- | --- |
| A `Thysanoptera` | 顯微圖版、圖鑑掃描、微距攝影（**部分甚至不是柑橘**，是禾本科葉片） | 蟲體佔畫面 5–50% |
| B `thirps_leaf_damage` | 使用者自己拍的 2048×1536 田間照 | 葉片銀白色食痕 |

兩者的表觀尺度差 **20–40 倍**。同一個 `Thrips` 標籤，有時指 25px 的蟲、
有時指 588px 的葉片區域——這比「感受野不足」更能解釋 53.91% 的召回率。

**決策是合併而不是刪除**，理由有兩個，而且第二個違反直覺：

1. 刪掉葉害子類會**失去唯一符合部署域的訊號**——域 A 的特寫在田間照裡永遠不會出現。
2. **刪了尺度反而更不一致**：只留蟲體是 11.1x，合併是 9.8x。

實測結果：Thrips 的 AP@0.5 從 v5 的 **0.572 → v5r 的 0.749**，
用的是原封不動的官方架構。**這是全專案唯一真正有效的改動。**

### 2.3 三處對 v5 方法的修改

| # | 改動 | 效果 |
| --- | --- | ---: |
| 1 | Aphid 丟棄面積等效邊長 `<20px` 的框（374 個，中位僅 7.6px） | 極差 26.0x → **9.4x** |
| 2 | Thrips 兩個子類合併為單一類別 | 極差 24.7x → **9.1x** |
| 3 | 檔名帶類別前綴，raw 與 aug 可由檔名區分 | — |

> **這條過濾不可全域套用。** Canker 有 46.0%、Scale_Insect 有 37.9% 的框短邊不足 20px，
> 但它們的 AP 是 0.795 與 0.855——**那是這兩類真實的物件尺寸，不是缺陷**。
> 過濾只在「同一類內部尺度分裂」時才成立。

> **詳見** [archive/v5r_說明_資料集建置與標註重整.md](archive/v5r_說明_資料集建置與標註重整.md)

## 3. 近重複影像跨 split 洩漏

### 3.1 v5r 的狀況

| 項目 | 數字 |
| --- | --- |
| 受影響類別 | `Scale_Insect`、`Thrips`、`Aphid`（**只有這三個 Pests 類別**） |
| 規模 | 三類 valid+test 共 544 張，**73 張（13.4%）與 train 近重複** |
| 最嚴重 | Thrips：valid 22.4% / test 21.1% |
| 乾淨的 | 四個 Diseases 類別與 Citrus_Leaf_Miner，**0 組** |

**成因**：手機連拍的相鄰影格，或同一張原圖被重複匯出（JPEG 參數不同）。

**為什麼既有檢查沒擋住**：`verify_dataset_v5r.py` 比對的是「檔案大小 ＋ 前 64KB md5」，
只能抓到逐位元相同的檔案。這次找到的重複**位元不同、畫面相同**。
後來才補上 `check_dataset_leakage.py` 用 dHash 做感知比對。

**這不是 v5r 引入的新問題**，是 v5 原始方法論（每類各自隨機 80/10/10）就有的缺陷。
v5、因而 v8 的歷史數字，大機率有相同問題。

### 3.2 現在的處理方式

**v5r 不修**——所有已發表的 v9 數字建立其上，重切分會讓它們全部作廢，
`build_dataset_v5r.py` 維持原樣以保可重現性。

**v5.5 起改用「近重複群組整群移進 train，不刪任何影像」**，
全類別零跨 split 近重複。v5.6 沿用同一機制。

> **詳見** [archive/v5r_記錄_近重複影像跨split洩漏查驗.md](archive/v5r_記錄_近重複影像跨split洩漏查驗.md)
> §1（查驗方法）、§3（三種機制附像素級驗證）、§4（對 P3 分層指標的量化影響）、
> §9（v5.5 的去洩漏機制）。

## 7. P3 的重新定義：不是小目標，是框定義不一致

**原本的敘述是錯的。** 原 P3 寫成「小目標定位精度：Thrips / Aphid 的
AP@0.5:0.95 僅為 AP@0.5 的 0.55 倍」——比值 0.55 是對的，「小目標」是錯的。

三條反證：

1. Thrips / Aphid 的框中位數是 **199 / 165 px**，近七成大於 128px，**不是小目標**。
2. 兩個真正的小目標類別反而更好：Scale_Insect（中位 27px）0.71、Canker（23.7px）0.64。
3. 換成**相對**誤差更清楚——寬度誤差中位數，小框類別 **5.6–6.7%**，
   大框類別 **6.7–8.3%**。若成因是「小目標難定位」，這張表應該完全相反。

**真正的問題**：同一組權重在 `Oily_Spot` 上的中位 IoU 是 **0.964**，
在 Thrips 葉害上是 **0.659**。**模型能力不是限制因素，目標定義才是。**

兩個直接沿用到今天的方法論結論：

- **主判準用中位 IoU 而非子域 AP**。bootstrap 500 次後，子域 AP 的 ±2SE 是 0.05–0.15，
  中位 IoU 只有 0.018–0.030。
- **刪除 Leaf_Damage 不會讓數字變好**（實測 valid −0.002 / test −0.012）。
  它的價值在清理回歸目標，不在美化指標。

> **詳見** [archive/v9_說明_P3定位精度改善與測試流程.md](archive/v9_說明_P3定位精度改善與測試流程.md)
> §1（完整反證與量測方法）、§2（三套方案）、§3（四臂測試流程與 bootstrap 判準）、
> 附錄 A（量測過程中修掉的三個 bug：EXIF、多邊形、[0,1] 夾取）。

## 8. 三條方法論鐵律

**一 · v8 的歷史數字與 v5r 之後完全不可比。**
不只量尺不同——感知雜湊比對顯示 v5r 的 valid 有 44.5%、test 有 47.5% 的影像
落在 v5 的 train 裡（兩版各自獨立切分），**不存在對 v8 乾淨的評估集**。
唯一合法的基準是重訓的 A0。

**二 · σ 是 epoch 內變異，不是 run 間變異**（後者通常更大）。
A3 / A1b / A1 的幅度夠大仍然成立；**A2（−1.9σ）與 A4（+0.7σ）是邊緣結果**，
要說「未達門檻」而不是「確定變差」。

**三 · per-class 差異不可過度解讀。**
四個實驗臂在 Canker / Black_Spot 上全部優於 A0、在 Leaf_Miner 上全部劣於 A0——
四個互不相干的改動同向，較可能是 A0 單次執行的運氣。
per-class 的 σ 遠大於整體的 0.00383（Leaf_Miner valid 僅 27 個實例）。

## 9. 踩過的坑

| 坑 | 症狀與辨識法 |
| --- | --- |
| **續跑會把權重換成 COCO 預訓練模型** | 最貴的一個。`ultralytics 8.4.121` 的 `resume=True` 會靜默換掉權重。**辨識法：`Transferred 902/902`** |
| `resume_from.pt` 其實不可用 | 被 `strip_optimizer` 蓋回去了。**可續跑的 ckpt 約 15.9 MB，被 strip 的只有 5.6 MB** |
| 續跑後 `results.csv` 有重疊列 | ep1–105 後接 ep102–160，共 164 列。算平台期要先拼接 `rows[:101] + rows[105:]` |
| **混淆矩陣與 mAP 不是同一個工作點** | `detect/val.py:54`：mAP 用 conf 0.001、混淆矩陣用 0.25 |
| 傳了 `conf=` 之後 mAP 與 F1 曲線都失真 | 高閾值必然壓低 mAP；F1 曲線只剩 [c,1]，極大值必落在左端點。只能取混淆矩陣與 P/R/F1 |
| `model.val()` 必須 `plots=True` | `detect/val.py:196` 把混淆矩陣包在 `if self.args.plots` 裡 |
| 估成本不要用 GFLOPs 推 | ADown 的 GFLOPs 是 0.86x，**實測慢 11%**。用實測 s/epoch |
