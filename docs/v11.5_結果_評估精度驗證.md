**四個判讀上的提醒**：

3. **跨類別誤判從 0 變成 4–5 個。** v9 在 test 上是 **0**（八類之間完全沒有互相誤判），

   **4–5 個在 665 個 TP 的規模下是 0.6%，不構成結構性問題**，
   但值得在下一輪繼續盯著。

4. **漏檢仍然集中在三個類別。** valid 的 183 個 FN 裡，

## 1. 摘要

1. **主要目標達成。全部九類的 pooled ±2SE ≤ 0.10，最差 0.099（`Citrus_Leaf_Miner`）。**
   這是 v5.6 存在的唯一理由，也是 v11 因為 `patience=30` 而報不出來的東西。
2. **而且更便宜**：3.06 小時，v11 是 4.42 小時，**省 1.36 小時**。
3. **`best.pt` 與 `last.pt` 實質等價**（差距 ≤ 0.004，且兩個指標方向不一致）。
   **改用 `last.pt` 幾乎沒有代價，卻換到「valid 可合法併計」**——這一輪最重要的方法論結論。
4. **模型表現：三版在同一批影像上打平。** v10 / v11 / v11.5 的 test mAP50 是
   0.809 / 0.800 / 0.788，全距 0.021；mAP50-95 是 0.606 / 0.603 / 0.599，全距 0.007。
5. **`Scale_Insect` 的矛盾徹底消失**：0.308（v10）→ 0.096（v11）→ **0.040**（v11.5）。
6. **`Thrips_Damage` 是唯一剩下的顯著矛盾**（0.202 / 門檻 0.165），而且比 v11 略大。
   它的成因是框定義不一致，不是樣本量——要靠人工工作包 A。
7. **一個我預估錯的地方**：平台期 σ 實測 0.0045，不是我在 notebook 裡寫的「0.002 附近」（§6）。

## 3. `best.pt` 與 `last.pt` 實質等價 —— 協定改動幾乎不用付代價

四次評估（2 權重 × 2 split）：

| | valid（挑選集） | | test（未參與） | |
| --- | ---: | ---: | ---: | ---: |
| | `last` | `best` | `last` | `best` |
| mAP50 | 0.82899 | 0.83280 | 0.80959 | 0.80898 |
| mAP50-95 | 0.63580 | 0.63876 | 0.60691 | 0.61078 |

| `best` − `last` | valid | test |
| --- | ---: | ---: |
| mAP50 | +0.00381 | **−0.00061** |
| mAP50-95 | +0.00296 | **+0.00387** |

**兩個指標在 test 上的方向相反，而且四個差距全部 ≤ 0.004。**
以本專案量到的 per-class 雜訊地板（±0.04）與 run 間全距（0.021）來看，
`best` 與 `last` 之間沒有可辨識的差異。

**這是本輪最有用的方法論結論**：先前為了「不要只看 `best.pt`」而堅持併報平台期平均，
現在有了更乾淨的作法——**直接用 `last.pt`，它既沒有選擇偏誤、又不比 `best.pt` 差**。

`best.pt` 高出平台期 **+0.00686 = 1.5σ**（平台期 0.63190 ± 0.00450）。
v10 是 2.8σ、v11 是 2.7σ——**灌水幅度明顯縮小**，因為固定輪數讓 `best` 的挑選範圍
從 84–99 輪縮到 70 輪，抽樣機會變少。

## 6. 收斂，以及我預估錯的一項

| 項目 | 值 |
| --- | --- |
| 實際輪數 | **70 / 70**（早停從未觸發，符合 `patience=0`） |
| 最佳輪次 | **ep53**（mAP50-95 = 0.63899） |
| `val/cls` 最低 | ep39 |
| 總時間 | 11,010 s = **3.06 小時**（每輪 157 s） |
| 平台期（末 16 輪） | 0.63190 ± **0.00450** |

**最佳輪次是 ep53，打破了 v8 / v9-A0 / v11 連續三次 ep69 的模式。**
但這兩者不直接可比——70 輪的餘弦排程把整個過程壓縮了，
ep53/70（76%）與 ep69/100（69%）在排程進度上其實相近。

### 我預估錯的地方

notebook 的「預期成果」第 4 項寫「平台期 σ 落在 **0.002 附近**」（依 v11 實測的 0.00202），
**實際是 0.00450**，高出一倍多。

原因不是資料集，是**平台期窗口在排程上的位置不同**：v11 的末 16 輪是 ep84–99，
餘弦退火早已把 lr 壓到接近零，指標自然很穩；v11.5 的末 16 輪是 ep55–70，
lr 還在明顯衰減，逐輪波動本來就比較大。

**這是我的預期沒考慮到排程長度，不是實驗出了問題。** 平台期 σ 只在同樣輪數之間可比。

### `close_mosaic` 第四次確認幫倒忙

| epoch | train/cls | val/cls | mAP50-95 |
| ---: | ---: | ---: | ---: |
| 57 | 0.7825 | 1.3723 | 0.6308 |

第 58 輪關閉後 `train/cls` 掉了 27%，`val/cls` 幾乎不動，**mAP50-95 反而下降**。
v9、v10、v11 都是同一個樣態。**四次了，可以當結論用**：
它只是讓模型更用力擬合訓練集。若要正式剔除，仍應當獨立一臂測。
