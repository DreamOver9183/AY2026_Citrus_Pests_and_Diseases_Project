## 1. 為什麼有 v5.7

`Thrips_Damage` 的 valid/test 矛盾三輪都沒收斂（0.285 → 0.190 → 0.202）。
工作包 A 量出根因：**框本身就不一致**。舊約定下兩人的中位 IoU 只有 0.746，
改成「一張葉子一個框」之後升到 0.899（判準 0.85）。
完整經過見 [v5.6_結果_工作包A標註一致性.md](v5.6_結果_工作包A標註一致性.md)。

v5.7 就是把那份新約定套回全類 208 張的結果。**除此之外什麼都沒動**——
切分規則、增強 profile、配額、seed 全部沿用 v5.6，這樣 `Thrips_Damage` 的變化
才能歸因到標註，而不是別的東西。

## 3. 驗收

### 3.1 Gate 0+：只准 `thirps_leaf_damage` 變（v5.7 新增）

v5.6 的 Gate 0 有一項是「來源樹與 v5.5 位元一致」。v5.7 就是為了重標而存在的，
那個資料夾**本來就該不一樣**——原樣套用只會得到一個必然失敗的紅字，久了會被習慣性忽略。
所以 Thrips 那個資料夾改問一個**更嚴格**的問題：它是不是「只」按預期變了。

| 檢查 | 結果 |
| --- | --- |
| Thrips 影像集合與 v5.5 相同（以內容 md5 比對） | ✓ 762 / 762 |

| 只有 `thirps_leaf_damage`（子類 1）變動 | ✓ 245 → 215 框，56 個檔案 |

其餘九個來源資料夾仍走原本的位元比對（5,496 個檔案全過）。

## 4. 建置過程中修掉的一個 bug

**`cv2.imread` 在非 ASCII 路徑下會靜默回傳 `None`。**

第一次建完 v5.7，train 只有 2,673 張（應為 7,264），每一類都是「增強 0/570」。
本專案的來源樹路徑是 `Datasets/1_原始影像/...`（中文），OpenCV 5.0.0 的 `imread`
走 Windows 的窄字元 API，讀不到就回 `None` 而**不丟例外**；
`write_augmented()` 把 `None` 當成「這張跳過」，於是整批增強產出 0 張，
而建置仍然「成功」結束。

**而且八道 Gate 會全綠**——它們檢查的是比例（增強圖與來源圖的框面積比之類），
不是絕對張數。一份沒有任何增強的資料集可以一路過關到訓練。

處理：

1. `build_dataset_v5r.py` 新增 `imread_any()` / `imwrite_any()`
   （`np.fromfile` + `cv2.imdecode` / `cv2.imencode` + `write_bytes`），
   `build_dataset_v5_6.py`、`copy_paste_clm.py` 的呼叫全部改掉。
2. **逐像素驗證 `imdecode` 一樣會套用 EXIF 方向**（與 `PIL.ImageOps.exif_transpose`
   的輸出完全相同），所以換過去不會改變任何既有資料的座標系。
3. 加保險：**任何類別配額不為 0 卻產出 0 張增強圖，當場中止**。

> `Datasets/2_處理與切分/v5.6` 現有的 7,264 張是路徑改版前建的，沒有受影響。
> 但今天任何人重建 v5.6 都會踩到同一個坑。

## 5. 已知限制

1. **`Thrips_Damage` 的 AP 不能與 v5.6 直接比。** 框的定義換了、中位面積變成 1.36 倍、
   框數從 245 降到 215。能比的是「valid/test 還矛不矛盾」，不是 AP 的絕對值。
   其餘八類的來源逐位元相同，可以比。

2. **重標後的類內一致性是 0.80–0.83，不是 0.899。**
   0.899 是「兩個人當場照新約定重畫 20 張」的水準；實際重標時 **152 / 208 張沿用了歷史框**
   （它們本來就只有一個框、已符合新約定，重畫的成本不會換到東西）。
   以工作包 A 的 20 張當基準實測，這批新標註對第一位是 0.832、對第二位 0.800。
   分開看，**沒動過的 12 張是 0.837、有改過的 8 張是 0.784**——沒動過的並沒有比較差，
   所以問題不在「152 張沒重畫」。差距集中在兩個已知原因：
   細長框的 IoU 天生吃虧、以及「多淡還算受害」沒有定義
   （見 [工作包 A 結果](v5.6_結果_工作包A標註一致性.md) §9.3）。**要寫進研究限制。**

3. **`build_dataset_v5_6.py` 第 233 / 268 行用 `PILImage.open(img).size` 取寬高，
   這個不套 EXIF。** Thrips 的 208 張葉害圖裡有 56 張帶旋轉標記，
   對它們會拿到對調的寬高。影響的是**框尺寸統計**（Gate 5/6 的比值、v5.6 §5 那類數字），
   不影響訓練資料本身——寫出影像走的是 `imread_any()`，會套 EXIF，與標註同一個座標系。
   `Aphid` 的 `equiv_px` 過濾只作用在 cid 7，薊馬不受影響。**未修，列為已知限制。**

4. **v5.7 的來源樹是 v5.6 的完整複本**（2.1 GB），不是用連結。
   好處是 v5.6 完全不受影響、可重現；代價是磁碟多佔 2.1 GB。
