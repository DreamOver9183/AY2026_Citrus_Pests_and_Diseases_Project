## 0. 摘要

1. **確認是在 v5.6 上訓練的。** 雲端 `summary.json` 寫 `"dataset": "v5.5"` 與 run 名
   `v5.6_v11` 矛盾，本機在 v5.6 上重評後**逐類 AP50 復現到小數第 3–4 位**（最大差 0.009），
   確認那只是評估腳本沒改到的舊字串。
2. **模型表現與 v10 持平。** 在**完全同一批影像**（v5.5 的 326 張 test）上，
   `mAP50 0.809 → 0.800`、`mAP50-95 0.606 → 0.603`——**沒有可宣稱的改變**。
3. **預先登記的 CLM 判準通過。** CLM 的 test AP50 `0.652 → 0.665`（+0.013），
   **砍掉 31% 的 train 沒有造成可測的損害**，不需要回退切分。
4. **v5.6 的量測目標達成了一半**：`Scale_Insect` 的 valid/test 矛盾
   **0.308 → 0.096，不再顯著**；`Thrips_Damage` 由 0.285 降到 0.190，**仍然顯著**。
5. **平台期 σ 由 0.00453 降到 0.00202**——評估集變大讓 epoch 間雜訊少了一半以上。
6. **但這一輪用了 `patience=30` 而不是預先登記的 `patience=0`**，
   於是 valid 不能與 test 併計，只能報 test → 最差 ±2SE 是 **0.140**，
   而不是計畫承諾的 0.099。**v5.6 的招牌目標這一輪還沒被證明**（§6）。
7. **兩個預測沒兌現**：旋轉修正沒有帶來 mAP50-95 的改善（§5）。

## 4. v5.6 真正交付的：量測面

v5.6 從設計上就不是為了讓模型變好，而是「[讓 per-class 指標變成可以下結論的東西](v11_計畫_資料擴充與切分重新設計.md)」。這一項有兌現。

| 類別 | v10 差 / 門檻 | 判定 | v11 差 / 門檻 | 判定 |
| --- | --- | --- | --- | --- |
| **Scale_Insect** | 0.308 / 0.163 | ✗ 顯著矛盾 | **0.096 / 0.098** | **✓ 消失** |
| Citrus_Leaf_Miner | 0.137 / 0.326 | ✓ | 0.078 / 0.198 | ✓ |
| Thrips | 0.076 / — | — | 0.071 / 0.194 | ✓ |
| **Thrips_Damage** | 0.285 / 0.214 | ✗ | **0.190 / 0.165** | ✗ **仍顯著** |

`Scale_Insect` 那個 0.308 的矛盾——[v10 報告](v10_結果_v5.5首次訓練評估.md) §3.1 列為
「本次最重要的發現」、「大部分 per-class 結論因此無法成立」的頭號問題——**被修掉了**。

**剩下 `Thrips_Damage` 一個。** 它的成因與樣本量無關，是框定義本身不一致
（R@0.75 僅 0.29），正是人工工作包 A 要回答的問題。

> 門檻是由 v10 實測的 ±2SE 依 1/√n 投影而來，不是重新 bootstrap 的。
> 真值要跑 `tools/diag_localization.py --bootstrap 500`。

## 5. 兩個沒兌現的預測

**一 · 旋轉修正沒有帶來 mAP50-95 的改善。**

[v5.6 計畫 §2.2](v5.6_計畫_無新拍攝的資料強化.md) 查到 v5r/v5.5 的增強圖框面積比原始圖
大 1.075–1.300 倍，並推論「這會特別傷 mAP@0.5:0.95 這種高 IoU 門檻的指標」。
v5.6 修掉之後（九類的框面積比全部回到 1.000），**同一批影像上的 mAP50-95 是 −0.003**。

修正本身是對的（Gate 5 實測 1.000，框尺寸分佈也如預期收縮），
但**它對指標的影響低於雜訊地板**，這個推論沒有得到支持。

**二 · ρ = −0.976 的外推只對了方向。**

CLM 的極差 9.9x → 9.0x，依該關係預期 AP 小幅上升。實際 +0.013——方向對，但在雜訊內。

## 6. 協定偏差：`patience=30` 讓招牌目標報不出來

v5.6 承諾的「全部九類 pooled ±2SE ≤ 0.10」有一個前提：
**`patience=0` ＋ 固定輪數，valid 才沒有參與任何決策、才能合法與 test 併計。**

這一輪用的是 `patience=30`，而且早停確實在 ep99 觸發（69 + 30）。
`best.pt` 是用 valid 挑的 → **valid 帶選擇偏誤，不能併計**。

| 類別 | 只報 test（本次） | valid+test 併計（原訂協定） |
| --- | ---: | ---: |
| Citrus_Leaf_Miner | **0.140** ✗ | 0.099 ✓ |
| Thrips | **0.137** ✗ | 0.097 ✓ |
| Thrips_Damage | **0.117** ✗ | 0.082 ✓ |
| Scale_Insect | 0.069 ✓ | 0.049 ✓ |
| 其餘五類 | 0.022–0.061 ✓ | 同 ✓ |
| **最差** | **0.140** | **0.099** |

**不是資料集做不到，是這次的訓練協定報不出來。**
