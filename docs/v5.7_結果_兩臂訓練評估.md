## 1. 判準 1：ext 臂未過，而且不是差一點

`Citrus_Leaf_Miner` 的 pooled AP50：base **0.7403** → ext **0.7612**，**+0.0209**。
判準是要超過逐類雜訊地板 ±0.04，沒過。

真正有說服力的不是這個數字本身，是**對照組**。base 與 ext 之間，
**只有 `Citrus_Leaf_Miner` 的訓練資料不一樣**，其餘八類逐位元相同。
那八類「應該」完全不動：

| 類別 | ext − base | 訓練資料有變嗎 |
| --- | ---: | --- |
| Oily_Spot | **+0.0211** | 沒有 |
| Black_Spot | +0.0144 | 沒有 |
| Canker | +0.0102 | 沒有 |
| Scale_Insect | +0.0052 | 沒有 |
| Sooty_Mold | +0.0000 | 沒有 |
| Thrips | −0.0007 | 沒有 |
| Aphid | −0.0070 | 沒有 |
| Thrips_Damage | +0.0012 | 沒有 |
| **Citrus_Leaf_Miner** | **+0.0209** | **多了 124 張** |

**`Oily_Spot` 什麼都沒加，動了 +0.0211；`Citrus_Leaf_Miner` 加了 124 張，動了 +0.0209。**
加了資料的那一類，移動幅度跟完全沒加的那一類一模一樣。

分 split 看更明顯——沒動過的類別在單一 split 上可以跑到 ±0.05：

| 類別 | Δvalid | Δtest |
| --- | ---: | ---: |
| Scale_Insect | **+0.0503** | **−0.0400** |
| Black_Spot | −0.0163 | **+0.0450** |
| Oily_Spot | +0.0053 | +0.0369 |
| **Citrus_Leaf_Miner** | +0.0233 | +0.0185 |

CLM 的移動比好幾個沒動過的類別還小。**這批外部影像沒有留下可偵測的訊號。**

### 為什麼會是這個結果

不是「外部資料沒用」的通則，是**這 124 張**沒用：

- B 包的 150 張裡有大量連拍，**實際只有約 20–25 片不同的葉子**。
- v11.5 在這批照片上只認出 7 張（5%）有潛葉蛾——**域差距很大**
  （公開資料集的離體葉放白紙上 vs 本專案的田間照）。
  域差距太大時，模型可以直接把它們當成另一個分佈記起來，不會遷移到田間照。
- 配額中性的設計讓它**擠掉了 124 張原本的增強圖**（CLM 的增強從 333 降到 209）。
  也就是說這是「124 張外部照片」對「124 張自有照片的增強」的對決，不是純粹的加法。

**別再花時間在這條路上**，除非能拿到與田間照同域的外部資料。

## 2. 判準 2：`Thrips_Damage` 的矛盾解除了

這是 v9 以來一直開著、三輪都沒收斂的問題：

| 輪次 | 資料集 | valid | test | gap | 顯著門檻 | |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| v9 | v5r | — | — | 0.285 | 0.214 | ✗ |
| v11 | v5.6 | — | — | 0.190 | 0.165 | ✗ |
| v11.5 | v5.6 | 0.6532 | 0.4515 | **−0.2017** | 0.165 | ✗ |
| **v5.7 base** | **v5.7** | 0.7243 | 0.8453 | **+0.1210** | 0.165 | **✓** |
| v5.7 ext | v5.7_ext | 0.7130 | 0.8590 | +0.1460 | 0.165 | ✓ |

三輪量下來都超標、而且不隨評估集擴大而收斂；**改掉標註之後一次就過了**。
這證實了工作包 A 的診斷：那個矛盾測到的是**標註噪聲**，不是模型的泛化差距。

收斂的方式也對得上：valid 只升 +0.071，**test 升了 +0.394**——
矛盾之所以消失，是因為原本被低估的那一邊（test）被修好了。

> ext 臂的 +0.1460 比 base 大，但兩臂的 `Thrips_Damage` 資料**完全相同**，
> 這 0.025 的差距就是 §1 那張表在講的 run-to-run 雜訊。

## 3. ⚠ 不要拿去報的數字

**`Thrips_Damage` 的 AP50 從 0.5524 升到 0.7848（+0.2324），這不是模型變好。**

新約定讓框變大（中位面積 11.30% → 15.40%，1.36 倍），
而 AP50 只要預測框與標註框的 IoU ≥ 0.5 就算命中——**框愈大愈容易達標**。
這一點在跑之前就寫進 [v5.7 驗收文件](v5.7_結果_資料集分析與驗收.md) §5，不是事後解釋。

連帶地，**整體 mAP50 也不能比**：

| | v5.6 (v11.5) | v5.7 base | v5.7 ext |
| --- | ---: | ---: | ---: |
| test mAP50（九類） | 0.80959 | 0.86118 | 0.86499 |
| test mAP50-95（九類） | 0.60691 | 0.64113 | 0.65040 |
| **八類平均 AP50（去掉 `Thrips_Damage`）** | **0.85268** | **0.85082** | **0.85884** |

九類的 test mAP50 看起來從 0.810 跳到 0.861（+0.052），**其中絕大部分是
`Thrips_Damage` 一類貢獻的**（它自己 test +0.394，除以 9 就是 +0.044）。
把它拿掉之後，八類平均是 0.8527 → 0.8508（**−0.002**）——**沒有變化**，
這才是誠實的答案。那八類的來源逐位元相同，是三輪之間唯一可以直接比的東西。

**交付數字仍然引用 v11.5 @ v5.6 的 test mAP50 0.80959。**
要改口徑必須說明「`Thrips_Damage` 換了框定義」，否則等於用放寬的標準報進步。

## 4. 其他觀察

| 項目 | v5.6 | v5.7 base | v5.7 ext |
| --- | ---: | ---: | ---: |
| 平台期 σ（mAP50，window 16） | 0.00256 | 0.00453 | 0.00381 |
| `best.pt` 高出平台期 | +0.00686（2.7σ） | +0.00817（1.8σ） | +0.00444（1.2σ） |
| 九類 pooled ±2SE 最差 | 0.099 | 0.099 | 0.099 |

- **九類 pooled ±2SE 全部 ≤ 0.10 的招牌目標仍然成立**（評估集張數沒變）。
- `best.pt` 的選擇偏誤這兩輪縮小到 1.2–1.8σ（v10 是 2.8σ、v11 是 2.7σ），
  但**協定不變**：主要結果一律報 `last.pt`。
- **`Scale_Insect` 接手成為唯一超標的類別**，但那一格測不出東西：它的資料在
  v5.6 → v5.7 → v5.7_ext 之間**一個位元都沒動**，三輪的 valid−test 卻是
  **0.040 / 0.174 / 0.084**——同一份資料、同一份訓練碼，落差自己在 0.04 到 0.17 之間跳。
  這只說明它的評估集（valid 35 / test 35）小到 gap 本身不穩定。
  它同時是 pooled AP50 最低的一類（0.63）。**下一個該量框一致性的就是它。**

### 一個要修的紀錄問題

三份 `summary.json` 的 `dataset` 欄**全都寫著 `"v5.6"`**，包括兩個 v5.7 的 run。
那是 `train_v11_5.ipynb` 裡寫死的字串——正是 v11 當初「花一半時間確認到底跑了哪一版」
的那個坑，v11.5 為此加了張數指紋，卻漏掉這一行本身。

**這三個 run 的身分不受影響**（`run` 欄與 `args.yaml` 的 `name` 都是對的，
而且 Step.2 的 provenance 斷言會擋下拿錯資料集），但欄位本身是錯的。
`tools/make_train_notebooks_v5_7.py` 已改成從 `_provenance.json` 取 `version` 與 `arm`，
往後生成的 notebook 不會再有這個問題。**已跑完的那兩份 `summary.json` 不動**
（`Train_output/` 是實驗產出，不手改）。

## 5. 下一步

**資料端也走到底了。** 盤點一下四輪的結論：

| 方向 | 結果 |
| --- | --- |
| 模型端（v9 六臂、v10、v11、v12s） | 十一種改動全部無效 |
| 訓練協定（v11.5） | 報得出來的精度修好了，模型沒變 |
| 部署端（v12 / v12.1 / v12.2） | 即時辨識不採用，已結案 |
| **資料端：外部影像（ext）** | **本輪無效** |
| **資料端：修標註（v5.7）** | **修掉了一個假問題，但沒有讓模型變好** |

剩下還沒試過、而且有依據的只有兩件：

1. **`Scale_Insect` 的標註一致性**——它是現在 pooled AP50 最低的一類（0.63），
   而且 §4 顯示它的 valid/test 落差在同一份資料上會從 0.04 跳到 0.17，
   **那正是「框本身不一致」的徵狀**（`Thrips_Damage` 當年就是這樣被抓出來的）。
   用工作包 A 同一套方法量一次（兩人各標 20 張、中位 IoU ≥ 0.85），
   成本是兩人各半小時。**這是目前投報率最高的一件事。**
2. **同域的新照片**。v11 計畫書算過需要 353 張；v5.6 證明「評估精度」不需要新照片，
   但「模型變好」到目前為止仍然沒有任何一條不需要新照片的路走通。

> 換句話說：**該用工程手段修的都修完了。** 再要進步，
> 要嘛修更多標註，要嘛補拍照片——這件事應該在週會上講清楚。
