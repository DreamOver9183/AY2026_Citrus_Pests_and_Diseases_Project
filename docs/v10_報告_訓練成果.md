**三個判讀上的提醒**：

1. **`Macro-Accuracy` 0.96–0.97 是虛高的，不應單獨引用。** 物件偵測沒有真正的
   真陰性，此處 TN 沿用 `N_total − TP − FP − FN` 的人為約定（與 v8／v9 報告一致，
   只為了讓表格能並排）。**`Detection Jaccard` 才是這個任務可信的整體正確率指標**，
   它略過 TN、只用 TP/FP/FN 計算，因此數值恆小於等於 Micro-F1。
2. **Macro 與 Micro 的差距揭露了類別不平衡。** test 上 Micro-Recall（0.8433）明顯高於
   Macro-Recall（0.7913），代表大類別（Canker、Aphid、Scale_Insect）拉高了整體數字，
   而小類別表現較差——per-class 表格（§4）必須一起看。
3. **valid 的 Detection Jaccard 明顯低於 test（0.6428 vs 0.7191）**，主因是 valid 的
   漏檢多出 65 個（173 vs 108）：

   | 類別 | valid FN | test FN | 差 |
   | --- | ---: | ---: | ---: |
   | Scale_Insect | 66 | 30 | **+36** |
   | Aphid | 38 | 13 | **+25** |
   | Thrips | 42 | 23 | **+19** |
   | Thrips_Damage | 7 | 20 | −13 |
   | 其餘五類 | 20 | 22 | −2 |
   | **合計** | **173** | **108** | **+65** |

   三個類別（Scale_Insect / Aphid / Thrips）就佔了 valid 全部漏檢的 **84%**，
   而 `Thrips_Damage` 的方向相反。成因見 §6.1——**這不是模型在兩個 split 上表現不同，
   而是兩個 split 的難度本來就不同**，且差距已被證實超過抽樣雜訊的範圍。

> **本表的數字不是模型的真實水準上限。** `best.pt` 高出平台期平均 2.8σ（§3.2），
> 平台期 mAP@0.5:0.95 = **0.578 ± 0.005** 才是無偏估計。

## 5. 與 v9/A0 的關係

| | v9/A0 @ v5r（8 類） | v10 @ v5.5（8 類等效） | 差 |
| --- | ---: | ---: | ---: |
| valid mAP50 | 0.867 | 0.821 | −0.046 |
| valid mAP50-95 | 0.654 | 0.634 | −0.020 |
| test mAP50 | 0.891 | 0.864 | −0.027 |
| test mAP50-95 | 0.678 | 0.658 | −0.021 |

**這張表不能當成勝負判定**，三個理由：

1. **v9 的數字受洩漏灌水**。v5r 的 valid/test 有 13.4% 影像與 train 近重複，v5.5 為 0%。
   v9 那一側含有一個未知但方向確定為正的偏誤。
2. **`Scale_Insect` 已是不同的任務**。同一個類別名稱底下量的不是同一件事。
3. **沒有乾淨的模型對模型比較可做**。把 v9 的權重拿來評 v5.5 也不行——v5r 的 train 與
   v5.5 的 valid/test 必然重疊（同一批來源、各自獨立隨機切分），評估會被洩漏汙染。

**能說的是**：在一份**零洩漏、多一個困難類別、且其中兩類已重新定義**的資料集上，
v10 拿到與 v9 相差 0.02–0.046 的成績；考慮到 v9 那側有正偏誤，**兩者實質接近持平**，
沒有證據顯示 v5.5 讓模型變差。

## 6. 誤差診斷

### 6.1 【最重要】評估集太小，valid 與 test 對同一類別給出超過 2σ 的相反答案

bootstrap 以影像為單位重抽樣 500 次（`tools/diag_localization.py`）：

| 類別 | split | n 框 | AP50 | ±2SE | R@0.5 | 中位 IoU |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| **Scale_Insect** | valid | 133 | 0.452 | 0.141 | 0.707 | 0.828 |
| **Scale_Insect** | test | 85 | 0.760 | 0.082 | 0.929 | 0.801 |
| **Thrips_Damage** | valid | 24 | 0.672 | 0.141 | 0.833 | 0.725 |
| **Thrips_Damage** | test | 31 | 0.387 | 0.161 | 0.548 | 0.727 |
| Citrus_Leaf_Miner | valid | 23 | 0.798 | 0.250 | 0.826 | 0.926 |
| Citrus_Leaf_Miner | test | 25 | 0.622 | 0.210 | 0.680 | 0.909 |

`Scale_Insect` 的 valid/test 差距 0.308（合成 2SE 0.163）、`Thrips_Damage` 差距 0.285
（合成 2SE 0.214），**兩者都超過門檻**——valid 與 test 不是可互換的樣本，而是難度不同的兩份資料。

以 `Scale_Insect` 為例，`<32px` 帶的 R@0.5 在 valid 是 0.626、test 是 0.931；valid 每張圖
5.3 個框、test 只有 3.4 個——valid 抽到的樣本又多又密。**成因是每類每 split 只有 20–25 張影像。**

> **這是目前最限制專案的問題，優先於任何模型改動。** 在評估集擴充之前，
> `Scale_Insect` / `Thrips_Damage` / `Citrus_Leaf_Miner` 的任何 per-class 結論都不成立。

### 6.2 Thrips 的小框召回是唯一跨 split 一致的真實弱點

| 尺寸帶 | valid R@0.5 | test R@0.5 |
| --- | ---: | ---: |
| `32–96px` | **0.529** | **0.429** |
| `96–256px` | 0.958 | 0.821 |
| `>256px` | **1.000** | **1.000** |

大框全中、小框漏掉一半以上，**兩個 split 方向一致**，不是抽樣雜訊。

成因已確認：v5.5 的去洩漏機制把 169 張近重複的田間連拍照（中位 247px，偏大）
整群移進 train，使 train 中位框尺寸（241px）遠高於 valid（112px）。
**模型學到的是大 Thrips。** 這是去洩漏機制的真實副作用。

### 6.3 Canker 重標成功

| | v5r（多邊形轉矩形） | v5.5（直接畫矩形，不含黃暈） |
| --- | ---: | ---: |
| valid AP50 / AP50-95 | 0.768 / 0.475 | **0.913 / 0.606** |
| test AP50 / AP50-95 | 0.845 / 0.543 | **0.906 / 0.556** |
| 尺度極差 | 7.5x | **6.1x** |

兩個 split 一致改善，是全表唯一明確且穩健的進步。對應
[P3 §2.4](archive/v9_說明_P3定位精度改善與測試流程.md) 的建議，**該建議有效**。

### 6.4 被否決的假設：增強並未破壞小框

v5.5 移除了 `Scale_Insect` 的「不增強」特例。實測增強圖與原始圖的統計：

| 類別 | 原始每圖框數 | 增強每圖框數 | 框數保留率 |
| --- | ---: | ---: | ---: |
| Scale_Insect | 4.78 | 4.85 | 101.5% |

## 7. 技術結論與後續改進建議

### 7.1 結論

1. **交付權重為 `best.pt` @ epoch 54**，test `mAP50 0.809 / mAP50-95 0.606`（9 類）；
   8 類等效為 `0.864 / 0.658`。**平台期平均 0.578 才是模型的真實水準。**
2. **與 v9 實質持平**，差距 0.02–0.046 且 v9 那側有洩漏正偏誤。
3. **本次最重要的產出不是模型，是「評估集不夠用」這個被量化證實的結論**——
   三個類別的 valid/test 差距超過 2σ。
4. **Canker 重標有效**，證實 P3 §2.4 的標註建議可行。
5. **Thrips 小框召回（0.43–0.53）是唯一跨 split 一致的真實弱點**，成因為去洩漏搬移
   造成的訓練/評估尺寸落差。

### 7.2 改進建議

| 優先 | 建議 | 依據 | 預期效益 |
| --- | --- | --- | --- |
| **P1** | **擴充 Citrus_Leaf_Miner / Thrips / Thrips_Damage 的評估集**（共需新增 353 張） | §6.1：三類的 ±2SE 為 0.161–0.210，valid/test 差距超過 2σ | 全部九類 test ±2SE ≤ 0.10；per-class 結論才開始可用 |
| **P2** | **改用「每類固定絕對評估量」而非固定百分比切分** | 現行 80/10/10 讓小池類別（CLM 201 張）只分到 20 張評估圖，大池類別（Aphid 806 張）卻有 76 張 | 統計解析度不再受池大小支配 |
| **P3** | **關閉早停、固定 60–70 輪、報平台期平均** | §3.1 最佳點在 ep54，84 輪中約 30 輪為過擬合；§3.2 best.pt 高出平台期 2.8σ | 省約 30% 算力；valid 不再參與決策後可合法併入評估集，±2SE 再降約 30% |

## 8. 研究限制與有效性聲明

1. **與 v9 的數字不可直接比較**（§5 的三個理由）。任何跨版本比較都必須同時說明
   類別數、標註定義與洩漏狀態的差異。
2. **三個類別的 per-class 數字不可單獨引用**：`Scale_Insect`、`Thrips_Damage`、
   `Citrus_Leaf_Miner` 的 valid/test 差距超過 2σ，真實水準只能給出區間
   （例如 Scale_Insect 的 AP50 落在 0.45–0.76 之間）。
3. **`best.pt` 的 0.591 含 best-of-N 抽樣偏誤**（高出平台期 2.8σ），
   平台期平均 0.578 才是無偏估計。
4. **`fitness` 的加權與訓練損失方向相反**：訓練時按框數分配梯度
   （`Thrips_Damage` 被降權至 0.44x），驗證時卻給它 1/9 的等權——
   小樣本類別的雜訊會直接汙染 checkpoint 選擇。
5. **v5.5 的切分與 v5r 不同**（每類獨立取種子＋去洩漏搬移），
   P3 診斷的固定評估子集（valid 299 / test 298 框）在 v5.5 上不成立。
6. **CPU 延遲不代表部署延遲**。本次本機評估為 fp32 CPU 結果。
