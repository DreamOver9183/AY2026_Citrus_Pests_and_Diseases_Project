# 歷史訓練與資料集紀錄

**用途**：把散在各版本報告裡的數字集中成一份可查表，並**明確標示哪些數字之間可以比較**。
**機器可讀版**：[training_history.json](training_history.json)（由各版本的原始輸出直接讀出，非手抄）
**維護方式**：每完成一次訓練就補一列。數字一律從 `results.csv` / `summary.json` /
`overview_metrics.json` 讀，不從報告內文轉抄。

> **這份文件只放數字與可比性判斷**，不放結論與推導——那些在各版本自己的報告裡。

## 5. 訓練協定的演進

| 期間 | 協定 | 問題 |
| --- | --- | --- |
| v8 – v10 | `patience=30`，報 `best.pt` | `best.pt` 由 valid 挑出，帶選擇偏誤；v10 實測高出平台期 2.8σ |
| v9 六臂 | 無早停，報**平台期平均** | 正確，但要同時解釋兩個數字 |
| v11 | `patience=30`，報 `best.pt` | 同上；且 valid 不可與 test 併計 → 最差 ±2SE 只能到 0.140 |
| **v11.5 起** | **`patience=0` ＋ 固定輪數，報 `last.pt`** | **目前的標準。** valid 未參與任何決策，可與 test 合法併計 |

**為什麼 `last.pt` 可以取代平台期平均**：v11.5 實測 `best` 與 `last` 的差距全部 ≤ 0.004，
且兩個指標在 test 上方向相反——沒有可辨識的差異。
改用 `last.pt` 不用付代價，卻讓 ±2SE 從 0.140 降到 **0.099**。

### valid/test 矛盾的收斂

| 類別 | v10 | v11 | v11.5 | **v5.7 base** | 門檻 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Scale_Insect | 0.308 ✗ | 0.096 | **0.040** ✓ | 0.174 ✗ | 0.098 |
| Thrips_Damage | 0.285 ✗ | 0.190 ✗ | 0.202 ✗ | **0.121** ✓ | 0.165 |

| Thrips | 0.076 | 0.071 | **0.079** ✓ | 0.117 ✓ | 0.194 |

`Thrips_Damage` 曾經是唯一沒有隨評估集擴大而收斂的——成因是**框定義不一致，不是樣本量**。
2026-09-13 依工作包 A 的新約定重標之後（v5.7），**一次就過**，而且是靠 test 從 0.4515 升到 0.8453 收斂的，
也就是原本被低估的那一邊被修好了。這件事從 v9 開跑就掛著，到這裡結案。

> **換 `Scale_Insect` 變成唯一超標的**（base 0.174 / 門檻 0.098）。但它的資料在
> v5.6 → v5.7 → v5.7_ext 之間一個位元都沒動，而三輪量到 0.040 / **0.174** / 0.084——
> **同一份資料、同一份訓練碼，落差自己在 0.04 到 0.17 之間跳。**
> 所以這一格測不出東西，它只是告訴我們 `Scale_Insect` 的評估集小到 gap 本身不穩定
> （valid 35 張 / test 35 張）。下一個該用工作包 A 那套方法去量框一致性的就是它。

## 6.5 預先登記判準的紀錄

把判準寫在跑之前，事後就不用爭論。目前有五次：

| 版本 | 問題 | 判準（開跑前寫死） | 實得 | 裁決 |
| --- | --- | --- | ---: | :-: |
| `v12s` | 模型容量是不是瓶頸？ | v5.6 test mAP50 **≥ 0.83959**（v11.5 + 0.03） | 0.81266（**+0.003**） | **✗ 未通過** |
| `v12.2` | 即時辨識要不要做？ | 延遲 ≤ 40 ms **且** test mAP50 ≥ 0.764 **且** 逐類跌幅 ≤ 0.10 | 延遲全過、精度最高 0.709 | **✗ 不採用** |
| **工作包 A** | `Thrips_Damage` 的框能不能一致定義？ | 兩人各標 20 張，中位 IoU **≥ 0.85** | 舊約定 0.746 ✗ → 一葉一框 **0.899** | **✓ 第二輪通過** |
| **`v5.7` ext 臂** | 外部影像對 CLM 有沒有幫助？ | ext − base 的 CLM AP50 **> 0.04**（逐類雜訊地板） | **+0.021** | **✗ 未通過** |
| **`v5.7` base** | 重標修得好 `Thrips_Damage` 的矛盾嗎？ | valid − test **< 0.165** | **+0.121** | **✓ 通過** |

`v12s` 的門檻訂 0.03 的理由：per-class 雜訊地板 ±0.04、三版 run 間全距 0.021，
低於 0.03 無法與雜訊區分。**結論：容量不是瓶頸，預算移回資料端。**

ext 臂未過的關鍵證據不是 +0.021 這個數字本身，而是**同一輪裡完全沒加資料的
`Oily_Spot` 也動了 +0.021**——加了 124 張的那一類，移動幅度跟什麼都沒加的一樣大。
