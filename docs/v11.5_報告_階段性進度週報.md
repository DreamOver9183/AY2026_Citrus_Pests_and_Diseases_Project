## 摘要

- **本期的主目標達成**：全部九類的評估誤差（±2SE）壓到 **≤ 0.10**（最差 0.099），
  **而且沒有新拍任何一張照片**。上一版計畫書原本要求補拍 353 張。
- **這件事之所以可能，是因為推翻了一個沒被檢驗的前提。** v11 計畫書假設
  「train 規模不能縮水」，量測後發現三個問題類別的近重複群組數是 **0**——
  評估集擴充完全不受洩漏限制，把既有影像從 train 移進評估集即可，代價只有 raw train −6.0%。
- **順帶查到一個存在於 v5r/v5.5、影響全部九個類別的缺陷**：增強用的任意角度旋轉
  讓標註框的面積系統性脹大 **1.075–1.300 倍**，而膨脹最嚴重的類別正是定位最差的類別。
  已修正，九類的框面積比全部回到 1.000。
- **模型指標沒有提升，而且我們現在有能力說「沒有提升」。** v10 / v11 / v11.5 在
  **完全同一批影像**上的 test mAP50 是 0.809 / 0.800 / 0.788，全距 0.021——
  這個量級就是 run 間變異。**本期的產出是量尺，不是模型。**
- **訓練協定改版並成為往後的標準**：`patience=0` ＋ 固定輪數 ＋ 報 `last.pt`。
  實測 `best.pt` 與 `last.pt` 沒有可辨識的差異，但改用後 valid 可合法併入評估，
  ±2SE 從 0.140 降到 0.099，**而且訓練時間少 1.36 小時**。
- **剩下一個未解問題**：`Thrips_Damage` 的 valid/test 矛盾三輪都沒收斂
  （0.285 → 0.190 → 0.202）。成因是框定義不一致，補樣本量救不了，
  下一步是已備妥的雙人標註一致性測試。

## 2. 主線：把量尺修好

### 2.1 問題是什麼

v10 訓練完成後量到：同一個類別，valid 與 test 給出**統計上顯著相反**的答案。

| 類別 | valid AP50 | test AP50 | 差 | 門檻 |
| --- | ---: | ---: | ---: | ---: |
| `Scale_Insect` | 0.437 | 0.745 | **0.308** | 0.163 |
| `Thrips_Damage` | 0.628 | 0.374 | **0.285** | 0.214 |

成因是**每個類別每個 split 只有 20–25 張影像**。這不是模型問題，是量尺問題——
**在量尺修好之前，任何模型端的改動都無法被驗證。**

### 2.2 原本的處方，以及它為什麼不必要

v11 計畫書開出的處方是補拍 **353 張**田間照。
但那份計畫有一條沒被檢驗的前提：**「train 維持現有規模不縮水」**。

量測之後發現，三個問題類別的**近重複群組數是 0**：

| 類別 | 影像池 | train 中「非近重複單張」 | 評估集擴充上限 |
| --- | ---: | ---: | ---: |
| Citrus_Leaf_Miner | 201 | **161（全部）** | 201 |
| Thrips_Damage | 208 | **166（全部）** | 208 |
| Scale_Insect | 251 | **201（全部）** | 251 |

也就是說，**把既有影像從 train 移進評估集完全不會踩到洩漏**。
放掉那條前提，代價只有 raw train −6.0%。

### 2.3 結果

| | v10 | v11 | **v11.5** |
| --- | ---: | ---: | ---: |
| 最差 ±2SE | 0.210 | 0.140 | **0.099 ✓** |
| 達標類別數 | 6 / 9 | 6 / 9 | **9 / 9** |
| 新拍照片 | — | 0 | **0** |

`Scale_Insect` 那個 0.308 的矛盾，經過兩輪降到 **0.040**，徹底消失。

## 3. 順帶查到的缺陷：全部九類的標註框都被撐大了

### 3.1 機制

Albumentations 旋轉標註框的做法是「把原框四個角轉一轉，再取新的外接矩形」。
對**任何**框這都是高估——**正方形框轉 15°，外接矩形面積就變成 1.50 倍**。
物件沒有變大，只有標註變鬆了。

v5r/v5.5 的增強管線帶著 `Affine(rotate=±15°, p=0.5)`。實測增強圖 vs 原始圖的框面積比：

| 類別 | 面積比 | | 類別 | 面積比 |
| --- | ---: | --- | --- | ---: |
| Sooty_Mold | 1.075 | | Citrus_Leaf_Miner | 1.136 |
| Aphid | 1.100 | | Thrips | 1.184 |
| Scale_Insect | 1.108 | | **Thrips_Damage** | **1.300** |
| Black_Spot | 1.115 | | | |
| Canker | 1.116 | | | |
| Oily_Spot | 1.135 | | | |

膨脹幅度由框的長寬比決定，而**長寬比最大的 `Thrips_Damage` 膨脹最嚴重——
它同時是定位最差的類別**（中位 IoU 0.725、R@0.75 僅 0.29）。
這個關係在九個類別上單調成立。

增強圖佔訓練集的 45–75%，所以模型有相當比例的監督訊號是「偏大的框」。

### 3.2 修正

**旋轉一律只用 90° 的整數倍**（90° 旋轉把緊貼的外接矩形映射成另一個緊貼的外接矩形，
零膨脹，而且提供 4 個朝向、角度多樣性比 ±15° 更高）。

驗收結果：**九類的框面積比全部回到 1.000**，框尺寸分佈也如預期收縮
（CLM 極差 9.9x → 9.0x）。

### 3.3 但它沒有讓指標變好

我們原本推論「框膨脹會特別傷 mAP@0.5:0.95」。修正之後，
同一批影像上的 mAP50-95 是 **−0.003**——**低於雜訊地板，這個推論沒有得到支持**。

修正本身是對的（框確實不再膨脹），但它對指標的影響量測不出來。

## 4. 模型表現：三版打平，而這次我們知道自己在說什麼

用 v5.6 的**巢狀切分**設計，可以取出與 v10 完全同一批的 326 張 test 影像：

| | v10 | v11 | v11.5 | 全距 |
| --- | ---: | ---: | ---: | ---: |
| test mAP50 | 0.809 | 0.800 | 0.788 | **0.021** |
| test mAP50-95 | 0.606 | 0.603 | 0.599 | **0.007** |

**沒有任何一版可以宣稱比另一版好。**

更重要的是我們量到了**雜訊地板**：資料完全沒動過的五個類別（`Oily_Spot`、`Canker`、
`Sooty_Mold`、`Black_Spot`、`Aphid`），它們的 AP50 在三版之間也移動了 −0.044 ～ +0.015。
**所以任何小於 ±0.04 的 per-class 差異都不該解讀。**

> 這是本期最有價值的方法論產出之一：以前我們會盯著 per-class 的 0.02 變化找原因，
> 現在知道那是雜訊。

## 5. 訓練協定改版

### 5.1 問題

`best.pt` 是從數十個檢查點裡挑 valid 上 `fitness` 最高的那一個——**帶選擇偏誤**。
v10 實測它高出平台期 2.8σ、v11 是 2.7σ。
更麻煩的是：既然 valid 參與了挑選，**valid 就不能再與 test 併計**，
評估樣本數少一半，±2SE 只能到 0.140。

### 5.2 改法與實測

改成 **`patience=0` ＋ 固定 70 輪 ＋ 報 `last.pt`**。四次評估（2 權重 × 2 split）：

| `best` − `last` | valid（挑選集） | test（未參與） |
| --- | ---: | ---: |
| mAP50 | +0.0038 | **−0.0006** |
| mAP50-95 | +0.0030 | **+0.0039** |

**四個差距全部 ≤ 0.004，而且兩個指標在 test 上方向相反**——沒有可辨識的差異。

| | v11 | **v11.5** |
| --- | ---: | ---: |
| 訓練時間 | 4.42 h | **3.06 h** |
| 最差 ±2SE | 0.140 | **0.099** |

**改用 `last.pt` 不用付代價，卻同時省下 1.36 小時、把評估精度做到目標。**
這已定為往後的標準協定。

### 5.3 附帶確認

`close_mosaic` **第四次**確認幫倒忙（v9/v10/v11/v11.5）：關閉後 `train/cls` 斷崖式
下降 27%，但 val 指標幾乎不動、有時反而下降。**它只是讓模型更用力擬合訓練集。**

## 7. 剩下的問題與下一步

### 7.1 `Thrips_Damage` —— 唯一沒有隨評估集擴大而收斂的

| | v10 | v11 | v11.5 | 門檻 |
| --- | ---: | ---: | ---: | ---: |
| valid/test 差 | 0.285 | 0.190 | **0.202** | 0.165 |

其他三個類別的矛盾都隨評估集變大而消失，只有它沒有。
**因為它的成因不是樣本量，是框定義本身不一致**（R@0.75 只有 0.29——找得到病徵但框不準）。

**下一步：工作包 A**——兩個人各標同樣 20 張，量兩人畫得像不像。

- 中位 IoU **≥ 0.85** → 約定可行，值得投入全類 208 張重標
- 中位 IoU **< 0.85** → 邊界本質上定不出來，**改為刪除該類別**

**兩種結果都是有用的答案。** 工作包與回收工具都已備妥，只差發派。

### 7.2 已知限制（照實記錄，不打算硬解）

`Thrips` 的 `32–96px` 小框帶：train 佔 10.4%、評估集佔 29.7%。
成因是去洩漏規則的必然後果（連拍的近重複群組一律進 train，而連拍傾向拍較大的目標）。
**縮放增強補不上**（實測：`scale` 開到 0.45 只從 10.9% 動到 14.4%），
**加權抽樣補得上但代價太大**（434 張 train 只有 34 張含帶內的框，會被各重複 14–19 次）。

### 7.3 建議的優先順序

| 優先 | 事項 |
| --- | --- |
| **P1** | 發派工作包 A（`Thrips_Damage` 雙人一致性測試）——唯一剩下的量尺問題 |
| **P2** | 跑 `diag_localization.py --bootstrap 500` 取得實測 ±2SE（目前是投影值） |
| P3 | 若要嚴格比較三版，用 `last.pt` 重評 v10 與 v11 |
| — | **不要**再從 `close_mosaic`、模型架構、損失函數找改善（六臂已證明無效，四次確認 `close_mosaic` 無用） |
