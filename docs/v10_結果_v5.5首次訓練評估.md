## 3. 三個發現

### 3.1 【最重要】評估集太小，valid 與 test 對同一類別給出超過 2σ 的相反答案

`tools/diag_localization.py` 的 bootstrap（以影像為單位重抽樣 500 次）：

| 類別 | split | n 框 | AP50 | ±2SE | R@0.5 | 中位 IoU |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| **Scale_Insect** | valid | 133 | 0.452 | **0.141** | 0.707 | 0.828 |
| **Scale_Insect** | test | 85 | 0.760 | **0.082** | 0.929 | 0.801 |
| **Thrips_Damage** | valid | 24 | 0.672 | **0.141** | 0.833 | 0.725 |
| **Thrips_Damage** | test | 31 | 0.387 | **0.161** | 0.548 | 0.727 |
| Citrus_Leaf_Miner | valid | 23 | 0.798 | 0.250 | 0.826 | 0.926 |
| Citrus_Leaf_Miner | test | 25 | 0.622 | 0.210 | 0.680 | 0.909 |

`Scale_Insect` 的 valid/test 差距 0.308，兩者合成的 2SE 是 0.163——**差距超過門檻**。
`Thrips_Damage` 差距 0.285，合成 2SE 0.214——**同樣超過**。

**這代表 valid 與 test 在這些類別上不是可互換的樣本，而是難度不同的兩份資料。**
成因是每個類別每個 split 只有 20–25 張影像，抽到哪幾張決定了難度。以 Scale_Insect 為例：

| 尺寸帶 | valid n | valid R@0.5 | test n | test R@0.5 |
| --- | ---: | ---: | ---: | ---: |
| `<32px` | 91 | **0.626** | 58 | **0.931** |
| `32–96px` | 40 | 0.875 | 27 | 0.926 |

valid 抽到的小框又多又難（每圖 5.3 框 vs test 的 3.4 框，見
[v5.5_結果_資料集分析.md](v5.5_結果_資料集分析.md) §4.1）。

> **實務結論**：**不要用單一 split 對 Scale_Insect / Thrips_Damage / Citrus_Leaf_Miner
> 下任何結論。** 這三類的真實水準只能說落在一個很寬的區間裡
> （例如 Scale_Insect 的 AP50 大約在 0.45–0.76 之間），本次資料無法再收斂。

### 3.2 Thrips 的小框召回是唯一跨 split 一致的真實弱點

| 尺寸帶 | valid R@0.5 | test R@0.5 |
| --- | ---: | ---: |
| Thrips `32–96px` | **0.529** | **0.429** |
| Thrips `96–256px` | 0.958 | 0.821 |
| Thrips `>256px` | **1.000** | **1.000** |

大框全中，小框漏掉一半以上，**兩個 split 方向一致**——這不是抽樣雜訊。

成因已在資料集分析報告 §4.1 記載並在此獲得證實：去洩漏搬移把 169 張近重複的
田間連拍照（中位 247px，偏大）整群移進 train，使 train 的中位框尺寸（241px）
遠高於 valid（112px）。**模型學到的是大 Thrips，評估時卻要面對小 Thrips。**

這是去洩漏機制的**真實副作用**——它換掉了洩漏，但代價是加深了 Thrips 的訓練/評估分佈落差。

### 3.3 Canker 重標成功，Scale_Insect 的增強假設被否決

**Canker**：AP50 0.913 / 0.906（v5r 為 0.768 / 0.845），AP50-95 0.606 / 0.556（v5r 0.475 / 0.543）。
兩個 split 一致改善，是全表唯一明確且穩健的進步。對應
[P3 §2.4](v9_說明_P3定位精度改善與測試流程.md) 的建議（改畫矩形、不含黃暈），**該建議有效**。

**被否決的假設**：v5.5 移除了 Scale_Insect 的「不增強」特例，我原本懷疑增強
（`GaussianBlur`、±15° 仿射）會破壞 27px 的小框。實測增強圖與原始圖的統計：

| 類別 | 原始每圖框數 | 增強每圖框數 | 框數保留率 |
| --- | ---: | ---: | ---: |
| Scale_Insect | 4.78 | 4.85 | 101.5% |
| Canker | 8.41 | 8.44 | 100.3% |
| Aphid | 2.85 | 2.84 | 99.4% |

**增強沒有吃掉任何框**，中位尺寸也相當。這條假設排除，不需要把特例改回去。

## 4. `best.pt` 高出平台期 2.8σ——預測的 best-of-N 灌水確實發生

| 項目 | 值 |
| --- | ---: |
| `best.pt` @ ep54 的 mAP50-95 | 0.59090 |
| 最後 16 輪平台期平均 | 0.57804 ± 0.00453 |
| 差距 | **+0.01286 = 2.8σ** |

訓練前已在 notebook 的判準說明中預測：`fitness` 是九類巨集平均、每類等權，而
`Thrips_Damage`（valid 僅 24 框）的單輪抽樣雜訊換算到聚合 `fitness` 約 ±0.017–0.028。
**實測的 +0.0129 正落在這個預測區間內。**

> **因此 `best.pt` 的 0.593 不應被當成模型的真實水準**，平台期平均 0.578 才是。
> 對外報告兩個都要列（沿用
> [v9_記錄_實驗重整與六臂消融.md](v9_記錄_實驗重整與六臂消融.md) 的既有作法）。

## 5. 與 v9/A0 的關係：為什麼不能直接比，以及能說什麼

| | v9/A0 @ v5r（8 類） | v10 @ v5.5（8 類等效） | 差 |
| --- | ---: | ---: | ---: |
| valid mAP50 | 0.867 | 0.821 | −0.046 |
| valid mAP50-95 | 0.654 | 0.634 | −0.020 |
| test mAP50 | 0.891 | 0.864 | −0.027 |
| test mAP50-95 | 0.678 | 0.658 | −0.021 |

**三個讓這張表不成立為「勝負判定」的理由**：

1. **v9 的數字受洩漏灌水**。v5r 的 valid/test 有 13.4% 影像與 train 近重複
   （[v5r_記錄_近重複影像跨split洩漏查驗.md](v5r_記錄_近重複影像跨split洩漏查驗.md)），
   v5.5 是 0%。v9 的 0.891 含有一個未知但方向確定為正的偏誤。
2. **Scale_Insect 已經是不同的任務**。1,119 張／15,379 框 → 251 張／1,179 框，
   標註約定也重新定義過。同一個類別名稱底下量的不是同一件事。
3. **沒有乾淨的模型對模型比較可做**。想把 v9 的權重拿來評 v5.5 也不行：
   v5r 的 train 與 v5.5 的 valid/test 必然重疊（同一批來源、各自獨立隨機切分），
   那樣的評估會被洩漏汙染。

**能說的是**：在一份**零洩漏、多一個困難類別、且其中兩類已重新定義**的資料集上，
v10 拿到與 v9 相差 0.02–0.046 的成績。考慮到 v9 那一側有正偏誤，
**兩者實質上接近持平**，沒有證據顯示 v5.5 讓模型變差。
