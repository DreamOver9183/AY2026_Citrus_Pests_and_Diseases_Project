### 兩個信心閾值的意義不同，不可混用

`detect/val.py:54` — `confusion_matrix_conf = 0.25 if conf is None else conf`。
也就是說**預設情況下 mAP 用 conf=0.001 計算，混淆矩陣卻是用 conf=0.25**，兩者不是同一個工作點。

| 跑法 | 可引用的欄位 | 不可引用 |
| --- | --- | --- |
| `val()`（不傳 conf） | mAP50 / mAP50-95 / per-class AP、混淆矩陣 @0.25 | — |
| `val(conf=0.4985)` | 混淆矩陣、P / R / F1 @0.4985 | **mAP**（高閾值必然壓低 mAP，是取法造成的假下降） |

### TN 的約定

物件偵測沒有真正的「真陰性」樣本。本文沿用 `docs/archive/v8_報告_模型訓練評估.md` §4.2 的
定義 `TN = N_total − TP − FP − FN`（`N_total` 為整個混淆矩陣的事件總數），
純粹是為了讓兩份報告的表格能並排比較。**Accuracy 與 FPR 兩欄因此帶有這個人為約定，
不應單獨引用**；判讀請以 Precision / Recall / F1 / AP 為準。

## 3. 誤差結構：**全部的錯誤都來自背景，沒有類別互相誤判**

test 的混淆矩陣（列 = 預測，欄 = 真實，conf = 0.25）：

```
                 Oily  Canker  Sooty  Black   Scale  Miner  Thrips  Aphid  背景(FP)
Oily_Spot          24       0      0      0       0      0       0      0        0
Canker              0     108      0      0       0      0       0      0       42
Sooty_Mold          0       0     32      0       0      0       0      0        1
Black_Spot          0       0      0     25       0      0       0      0        1
Scale_Insect        0       0      0      0    1222      0       0      0      450
Citrus_Leaf_Miner   0       0      0      0       0     20       0      0        4
Thrips              0       0      0      0       0      0      94      0       21
Aphid               0       0      0      0       0      0       0    193       57
背景(FN)            0      12      0      0     207     13      12     27        0
```

**8×8 區塊的跨類別誤判總數為 0。** 模型不會把任一種病蟲害認成另一種——
所有錯誤都是「把背景當成目標」（FP 576）或「把目標當成背景」（FN 271）。
（valid 上跨類別誤判為 8 例，其中 4 例是 Thrips 被判成 Aphid；test 上連這個都沒有。）

這把後續的改善方向收斂成一個問題：**背景抑制**，而不是特徵區辨力。

**兩個主要誤差源**：

| 誤差源 | 數量 | 佔比 |
| --- | ---: | --- |
| Scale_Insect 背景誤報 | 450 | 佔全部 FP 的 **78%** |
| Scale_Insect 漏檢 | 207 | 佔全部 FN 的 **76%** |

Scale_Insect 的 FPR 高達 0.3961，單類 Accuracy 只有 0.7439，是唯一一個明顯拖累
整體 Micro 指標的類別。這與 v8 報告 §5.2 的診斷方向一致（v8 當時是 615 FP / FPR 39.30%），
但**兩者的資料集不同，數字不可直接相減**。

## 4. 部署工作點：conf 該設多少

| Split | conf | ΣTP | ΣFP | ΣFN | Micro-P | Micro-R | Micro-F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| valid | 0.25（預設） | 1841 | 704 | 272 | 0.7234 | 0.8713 | 0.7905 |
| valid | 0.4985 | 1631 | **295** | 482 | **0.8468** | 0.7719 | **0.8076** |
| test | 0.25（預設） | 1718 | 576 | 271 | 0.7489 | 0.8638 | 0.8022 |
| test | 0.4985 | 1514 | **247** | 475 | **0.8597** | 0.7612 | 0.8075 |

把閾值從 0.25 提高到 0.4985：

- **誤報減少約 57%**（valid 704→295，test 576→247）
- 漏檢增加約 75%（valid 272→482，test 271→475）
- **Micro-F1 幾乎不變**（valid 0.7905→0.8076，test 0.8022→0.8075）

Scale_Insect 的背景誤報：valid 563 → 224、test 450 → 190。

> **最佳 F1 截斷點在兩個 split 上不一致**：valid 0.4985、test 0.3954。
> 這個差距（0.10）說明該值本身有相當的取樣變異，**不應把 0.4985 當成精確的最優值**。
> 建議：以 **conf ≈ 0.40–0.50** 作為部署區間；若應用場景重視「不漏報」（例如田間預警）
> 則取下界甚至沿用 0.25，若重視「不誤報」則取上界。F1 在這整段區間內幾乎是平的，
> 閾值選擇應由應用端的成本結構決定，而不是由 F1 決定。

## 5. 限制

1. **不與 v8 並列比較。** v5 與 v5r 是各自獨立切分的，感知雜湊比對顯示 v5r 的 valid 有
   44.5%、test 有 47.5% 的影像出現在 v5 的訓練集中——**不存在一份能公平評估 v8 的 v5r 資料**。
   且 v8 的既有報告本身只有 valid 數字，沒有 test 數字。本文所有數字均為 A0 單獨的絕對表現。
2. **訓練集有 57.8% 是合成影像**（`synth_aug_cls*`），而 valid / test 全部是 raw 影像。
   兩者的分佈存在系統性差異。
3. **五個類別的實例數 ≤ 33**（Oily_Spot 24、Black_Spot 25、Sooty_Mold 32、
   Citrus_Leaf_Miner 33、以及 valid 的 Oily_Spot 24 / Black_Spot 25 / Leaf_Miner 27）。
   這些類別每漏檢一個，Recall 就掉 3–4 個百分點，**其 AP 的解析度比本文想討論的差異還粗**。
4. **Scale_Insect 佔 test 全部實例的 72%**，而在訓練集只佔 25.6%。Micro 指標被這一類主導。
5. **CPU 延遲不代表部署延遲。** 本次量到的 158 ms/張是 fp32 CPU 的結果，
   GPU / fp16 下會低一個量級，若報告需要延遲數字應另行在目標硬體上量測。
6. **Accuracy 與 FPR 帶有人為的 TN 約定**（見 §0），僅供與 v8 報告的表格形狀對齊，
   不應單獨引用。

## 6. 結論

- **最終交付權重為 `best.pt` @ epoch 69**，test 集表現 **mAP@0.5 = 0.8908**、
  **mAP@0.5:0.95 = 0.6783**、Precision 0.8995、Recall 0.8614。
- **模型沒有過擬合 valid**：test 的所有主要指標都不低於 valid。
- **誤差結構單純**：沒有任何類別互相誤判，全部錯誤都是背景 FP / FN，
  且 Scale_Insect 一類就佔了 78% 的誤報與 76% 的漏檢。
- **後續若要繼續改善，方向明確且都在資料端**：
  （a）Scale_Insect 的背景抑制——增加負樣本或困難負例；
  （b）Citrus_Leaf_Miner 的漏檢——該類實例數過少（train 佔 4.3%），且 Recall 僅 0.61；
  （c）四個小目標類別的定位精度（AP50-95 只有 AP50 的 0.5–0.6 倍）。
  **這三項都不是架構問題**——階段 2 的六臂消融已證明架構層面的改動全數無效。
