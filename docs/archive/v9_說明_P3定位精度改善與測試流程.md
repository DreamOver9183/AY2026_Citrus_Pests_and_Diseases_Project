# P3 定位精度：問題定義、改善方案與測試流程

**日期**：2026-09-02
**診斷工具**：[tools/diag_localization.py](../../tools/diag_localization.py)
**原始輸出**：`Train Code/v9/Train_output/Phase4/P3_diag/{valid,test}_{strata,bands,residuals}.csv`
**評估權重**：`best.pt` @ epoch 69（與最終交付權重相同，未重訓）

---

## 0. 摘要

1. **原本的 P3 敘述是錯的。** 「小目標定位精度」與資料自身的統計矛盾——Thrips / Aphid 的框中位數是 199 / 165 px，近七成大於 128px；真正的小目標 Scale_Insect（中位 27px）比值反而更好。**相對尺度上，大框類別框得比小框類別還差**（寬度誤差中位數 8.3% vs 5.6%）。
2. **真正的問題是框定義不一致**，而且是三個彼此獨立的問題：Thrips 的葉害子域沒有客觀邊界、蟲體特寫子域的尺寸約定分歧、`<32px` 類別已經貼到標註噪聲地板。
3. **同一組權重在 Oily_Spot 上的中位 IoU 是 0.964**，在 Thrips/Damage 上是 0.659。模型能力不是限制因素，目標定義才是。
4. **刪除 Leaf_Damage 不會讓 Thrips 的數字變好**（實測評估端影響 valid −0.002 / test −0.012）。它的價值在於清理回歸目標，不在於美化指標。
5. 主判準應改用**中位 IoU**而非子域 AP：bootstrap 500 次後，子域 AP 的 ±2SE 是 0.05–0.15，中位 IoU 只有 0.018–0.030。

## 1. 問題定義

### 1.1 舊敘述與它為什麼不成立

> **小目標定位精度**：Thrips / Aphid 的 AP@0.5:0.95 僅為 AP@0.5 的 0.55 倍

### 1.2 量測方法

四項量測，全部在本機 CPU 完成（約 12 分鐘）：

| # | 量測 | 作法 |
| --- | --- | --- |
| 1 | **provenance 還原** | valid / test 不做增強，`build_dataset_v5r.write_sample()` 是位元複製，故可用 md5 對回來源影像，取得每個框的來源子類。**還原率 322/322 與 326/326，100%** |
| 2 | **子域分層 AP** | 其他子域的 GT 視為 ignore（COCO crowd 的標準作法），避開「背景 FP 無法歸屬子域」的問題 |

| 4 | **bootstrap** | 以**影像**為單位重抽樣 500 次，給出 AP50-95、R@0.75、中位 IoU 的標準誤 |

### 1.4 三個彼此獨立的問題

**問題 A · `Thrips_Leaf_Damage` 是全表定位最差的子域**

中位 IoU 0.659 / 0.709，是十個分層裡最低的。R@0.5 有 0.700 / 0.905，但 R@0.75 只剩 0.350 / 0.381——**腰斬**。找得到，框不準。

兩個 oracle 都只抬到 0.77–0.78，代表中心與尺寸**同時**畫不準。這是「沒有客觀邊界」的特徵：銀白色食痕從哪裡開始、到哪裡結束，是人為約定；相鄰兩塊食痕該合成一框還是分成兩框，也沒有規則。

**問題 B · 蟲體特寫子域的尺寸誤差是定義性的，不是像素級的**

Thrips/Insect 中位 IoU 0.781 / 0.810，Aphid/Insect 0.790 / 0.782。兩者的 `orc_s`（0.867 / 0.894）都明顯高於 `orc_c`（0.813 / 0.859）——**尺寸誤差主導**，位置沒問題。

寬度差中位數 8.3%，在 222px 的框上等於 18px。這不是像素精度可以解釋的量級。

對照組：**同一個權重、同一次訓練，在 Oily_Spot 上的中位 IoU 是 0.964，寬度差的 p75 只有 0.03。** 模型有能力框到 0.96；差別在目標定義是否一致。

v5r 建置說明 §2 已記錄成因：蟲體子域本身混了顯微圖版、圖鑑掃描與微距攝影（部分甚至不是柑橘），不同來源對「框到哪」的約定不同。合併子類壓下了尺度極差（24.7x → 9.1x）並讓 AP50 從 0.572 拉到 0.910，但沒有統一框的定義——**這正是 AP50 好而 AP50-95 差的機制**。

**問題 C · `<32px` 帶已經逼近標註噪聲地板**

Scale_Insect `<32px`：中位 IoU 0.837 / 0.834，模型與標註的寬度差中位數只有 **1.2–1.4px**。

IoU 對小框的敏感度（同心正方框，每邊差 e px）：

| 邊長 | e=0.5px | e=1px | e=2px | e=3px |
| ---: | ---: | ---: | ---: | ---: |
| 20px | 0.907 | 0.826 | 0.694 | 0.592 |
| **26px** | 0.927 | **0.862** | 0.751 | 0.660 |
| 32px | 0.940 | 0.886 | 0.790 | 0.709 |
| 48px | 0.960 | 0.922 | 0.852 | 0.790 |
| 96px | 0.979 | 0.960 | 0.922 | 0.886 |

26px 的框，每邊只差 1px，IoU 就只剩 0.862。**模型已經貼著標註走了**，AP50-95 = 0.61 基本上就是這份標註品質的上限。

Canker 則不同：`<32px` 中位 IoU 0.836 / 0.853，`32–96px` 是 0.846 / 0.857——**與尺寸無關**。Scale_Insect 是尺寸相依的（0.837 → 0.905），Canker 不是。所以 Canker 的問題不在像素精度，而在病灶邊界的定義。

### 1.5 改寫後的 P3

> **P3 · Thrips / Aphid 的框定義不一致，以及 `<32px` 類別的標註像素精度已達地板**
>
> Thrips / Aphid 的 AP50-95 / AP50 僅 0.55，但兩者的框中位數是 199 / 165px，近七成大於 128px——不是小目標問題。成因有二：(a) 兩類各自合併了「蟲體」與「葉害」兩種沒有共同邊界約定的子域，其中 `Thrips_Leaf_Damage` 的中位 IoU 0.659 是全表最低；(b) 蟲體子域內部混了顯微／圖鑑／微距三種來源，尺寸約定分歧達 8%。
>
> 另一方面，Scale_Insect 與 Canker 的 `<32px` 框，模型與標註的差距中位數只有 1.2–1.5px，已達人工標註的物理極限，**不應列為模型端的改善目標**。

## 2. 解決方案

### 2.1 前提：刪除與拆類都會改變評估集，數字不可直接比

只要動了 valid / test 的框，mAP 的分母就變了，新舊數字不可比。因此整套流程建立在一個**固定評估子集**上：

**主判準子集 = `Thrips/Insect` + `Aphid/Insect`，valid 299 框、test 298 框。**

這個集合在下述所有方案下都完全不變（刪除與拆類都只影響 Damage 子域）。`diag_localization.py` 的 ignore 機制讓其他子域的預測既不算 TP 也不算 FP，因此可以在資料集變動的情況下比較。

### 2.2 方案 A：刪除 Leaf_Damage 子域

**關鍵前提已驗證：兩個子域從不共存於同一張影像。** 每一張含 Damage 框的影像**只有** Damage 框，因此刪除是「整張移除」，不需要編輯任何一個標註檔。

| 子域 | 來源合計 | train 圖/框 | valid 圖/框 | test 圖/框 | 混合圖 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `Thrips_Leaf_Damage` | 208 圖 / 245 框 | 171 / 204 | 16 / 20 | 21 / 21 | **0** |
| `Aphid_Leaf_Damage` | 34 圖 / 96 框 | 29 / 85 | 1 / 3 | 3 / 7 | **0** |

兩者的處置**不同**：

#### `Aphid_Leaf_Damage` → 刪除

| 理由 | 數字 |
| --- | --- |
| 樣本量不足以學會第二種框定義 | 96 框，佔 Aphid 全體 2,767 框的 **3.5%** |
| 也不足以驗證有沒有學會 | valid 只有 3 框、test 只有 7 框；AP 的 ±2SE 已達 0.022 / 0.067，而 AP 本身是 0.014 / 0.059 |
| 撐不起一個「域」 | 34 張影像 |

它引入了第二種框定義，卻既學不會也量不準——這是純粹的回歸目標噪聲。**刪除。**

#### `Thrips_Leaf_Damage` → 不要刪，改拆類（見方案 B）

三個理由：

1. **它是真實存在的子域**：245 框 / 208 圖，而且是 [v5r 說明](v5r_說明_資料集建置與標註重整.md) §3 認定的**唯一符合田間部署域的 Thrips 訊號**（域 A 的蟲體特寫是圖鑑與微距照，在 2048×1536 的田間照裡永遠不會出現那個尺度）。刪掉它等於用部署能力換指標。
2. **刪掉它不會讓數字變好。** 實測：`Thrips/Insect` 的 AP50-95 是 0.396 / 0.493，而合併類 Thrips 的官方數字是 0.398 / 0.505——**valid −0.002、test −0.012**。AP 由多數子域主導，20 個框的權重不足以移動它。
3. 真正的期望效益來自「不再逼同一個回歸頭擬合兩種框定義」，那需要**拆類**，不是刪除。

> **若你仍決定刪除 `Thrips_Leaf_Damage`**（例如專題只求指標、不談部署）：
> 代價是 train 的原始影像從 610 張降到 439 張（**−28%**），增強配額 `min(4×439, 1200)` 仍可補回 1200 張，但原始多樣性下降；valid / test 各少 16 / 21 張。
> 並且必須在報告限制章節寫明：模型不再涵蓋田間葉害域。
> 依上述第 2 點，**預期指標增益接近零**——這個選項的理由只能是「簡化」，不能是「提升」。

### 2.3 方案 B：Thrips 拆類（建議與方案 A 併用）

8 類 → 9 類，新增 `Thrips_Damage`：

| id | 類別 | 框數（來源） |
| ---: | --- | ---: |
| 6 | `Thrips`（僅蟲體 `Thysanoptera`） | 837 |
| 8 | `Thrips_Damage`（`thirps_leaf_damage`） | 245 |

兩種框定義分開學，回歸頭不再需要同時擬合兩個互相矛盾的目標。

**必要配套**：

- 報數字時**同時報 9 類 mAP 與「合併回 8 類」的等效 mAP**，否則與現有報告不可比。
- `Thrips_Damage` 本身的 AP **不可信**——valid 20 框 / test 21 框，±2SE 已達 0.147 / 0.125。這個新類別只看中位 IoU，不看 AP。
- 拆類後 `mAP` 的類別平均被一個小類稀釋，8 類等效值才是對外的數字。

### 2.4 方案 C：`<32px` 的標註調整（Scale_Insect / Canker）

兩類的病因不同，處置也不同。

#### Scale_Insect —— 尺寸相依，問題在標註作業的像素精度

現況：`<32px` 中位 IoU 0.837，`32–96px` 0.905。模型與標註的寬度差中位數 1.2–1.4px。**模型已經貼著標註走**，要改善只能改善標註本身。

| # | 規則 | 依據 |
| ---: | --- | --- |
| 1 | **放大到 ≥400% 再拉框。** 禁止在縮圖或整圖檢視下標註小目標 | 26px 的目標在 100% 檢視下只有 26 個螢幕像素，滑鼠移動一格就是 4% 的邊長誤差。這條的效益最大且成本最低 |
| 2 | **寫死蠟殼約定：框「含蠟殼外緣」。** 四個亞型（Black / Brown / Green Coffee / White）一律適用 | 白色蠟殼的視覺邊界比蟲體本身大 20–30%；四亞型合併成一類後若各採各的約定，就會產生 8–10% 的系統性尺寸分歧，正是實測到的量級。選「含蠟殼」是因為田間肉眼可見的就是蠟殼 |
| 3 | **群聚分框規則**：個體可分辨時一隻一框；相鄰個體重疊超過一半時合併為一框；框不得跨越葉脈 | 介殼蟲成片附著，沒有規則時同一片蟲群在不同人手上會產生 1 框或 15 框。這同時是 Scale_Insect 佔全體誤報 78.1% 的可能來源之一 |
| 4 | **下限：面積等效邊長 < 12px 的目標不標，改列 ignore** | 12px 的框每邊差 1px，IoU 只有 0.69——標了只會製造無法達成的回歸目標與假漏檢 |
| 5 | **重標後量標註者一致性**：抽 60 框，隔 3 天由同一人重標，算兩次的中位 IoU | 這個數字就是 AP50-95 的上限。低於 0.85 就停手（見 §3.5） |

> **禁忌**：**不可**把 Aphid 的 `<20px` 過濾規則套到 Scale_Insect。Scale_Insect 有 69% 的框在 32px 以下，20px 門檻會砍掉大量真實目標。[v5r 說明](v5r_說明_資料集建置與標註重整.md) §4 已記錄此禁忌：過濾只在「同一類內部尺度分裂」時成立。此處建議的 12px 下限遠低於該分佈的主體，且以 ignore 而非刪除處理。

#### Canker —— 尺寸無關，問題在病灶邊界的定義

現況：`<32px` 0.836 / 0.853，`32–96px` 0.846 / 0.857——兩帶一樣差。這排除了像素精度假說。

| # | 規則 | 依據 |
| ---: | --- | --- |
| 1 | **框「木栓化病斑本體」，不含黃暈（chlorotic halo）** | 兩種約定的面積差可達 1.5–2 倍。選本體是因為黃暈邊界隨光照與品種變化，本體不會 |
| 2 | **重標時直接畫矩形，不要走多邊形** | Canker 來源是多邊形轉外接矩形（v5r 建置說明 §5）。多邊形若沿黃暈畫，外接矩形會系統性偏大——實測 `bias_w` 為 +0.03～+0.05（預測比標註寬 2–4%），方向一致 |
| 3 | **沿葉緣連成一片的病斑需要分框規則**（同 Scale_Insect 第 3 條） | 潰瘍常連片 |
| 4 | 同樣做一致性量測 | 同上 |

### 2.5 明確不要做的事

| 不要做 | 原因 |
| --- | --- |
| 提高 `imgsz` | A4（800）已測：+0.7σ 未達門檻、成本 1.59x。而且問題不在解析度 |
| 換 IoU 損失 | A1 / A1b（Wise-Inner-MPDIoU）是 −3.8σ / −4.8σ |
| 調 `box` 權重追 AP50-95 | 在標註一致性量出來之前，那是在擬合噪聲。另注意本架構是 `end2end=True` / `reg_max=1`（無 DFL 分布），沒有「把回歸分布調寬」這個選項可用 |
| 用「刪除 Leaf_Damage」美化報告數字 | 實測評估端影響 valid −0.002 / test −0.012，不會變好 |
| 把 Canker 也當成小目標處理 | 它的誤差與尺寸無關，像素級措施對它無效 |

## 3. 測試流程

### 3.1 判準

**主判準：`Thrips/Insect` + `Aphid/Insect` 的中位 IoU**（固定子集，valid 299 / test 298 框）

為什麼不用子域 AP——bootstrap 500 次的 ±2SE 對照：

| 指標 | Thrips/Insect | Aphid/Insect | Scale_Insect |
| --- | ---: | ---: | ---: |
| AP50-95 | 0.106 / 0.076 | 0.061 / 0.050 | 0.040 / 0.041 |
| R@0.75 | 0.160 / 0.120 | 0.092 / 0.079 | 0.032 / 0.040 |
| **中位 IoU** | **0.027 / 0.025** | **0.030 / 0.018** | **0.013 / 0.016** |

*（valid / test；AP 還受 PR 曲線形狀影響，逐框統計穩定得多）*

**通過門檻**：Δ 中位 IoU > 2×SE **且 valid 與 test 同號**。

| 分層 | valid 需超過 | test 需超過 |
| --- | ---: | ---: |
| Thrips/Insect | +0.027 | +0.025 |
| Aphid/Insect | +0.030 | +0.018 |

**次判準**：R@0.75、8 類等效 mAP50-95（沿用 A0 的 2σ 門檻 = 0.64165）。
**必看但不作判準**：`Thrips_Damage` 的中位 IoU（n=20/21，AP 完全不可信）。

> **這裡的 SE 只涵蓋評估集抽樣，不含 run 間變異**（後者只能靠重訓量，通常更大，見 [v9_記錄_實驗重整與六臂消融.md](v9_記錄_實驗重整與六臂消融.md) 的判準討論）。要求「兩個 split 同號」是對此的部分補償，不是完整補償。C0 臂的作用就是補上這一塊。

### 3.2 實驗臂

| 臂 | 訓練資料 | 類別數 | 回答的問題 | 成本 |
| --- | --- | ---: | --- | ---: |
| **C0** | v5r 原樣（= A0 設定重跑一次） | 8 | 基準，並提供 run 間變異的第二個樣本 | 1.00x |
| **C1** | C0 − `Aphid_Leaf_Damage`（29 張 train 圖） | 8 | 96 框的第二種定義是否在傷害 Aphid | 1.00x |
| **C2** | C1 + Thrips 拆為 `Thrips` / `Thrips_Damage` | 9 | 兩種框定義分開學，蟲體域會不會變準 | 1.00x |
| **C3** | C2 + Scale_Insect 依 §2.4 重標 | 9 | 標註規則的效益（最貴，最後做） | 1.00x + 人工 |

共同設定：60 輪、`patience = EPOCHS`（關閉早停，否則各臂平台期窗口不一致）、其餘沿用 A0。
`close_mosaic` 由 `EPOCHS` 自動推導，不要手填。

**C0 不是多餘的。** A0 只跑過一次，目前所有 σ 都是 epoch 內變異。C0 提供同設定的第二次執行，讓你第一次能估到 run 間差異——若 C0 與 A0 的差距本身就超過 §3.1 的門檻，那後面三臂的結論全部無效，必須先擴充重複次數。

### 3.3 執行步驟

**Step 1 · 本機：建立資料集變體**

`tools/build_dataset_v5r.py` 需要兩個新參數（目前尚未實作）：

```bash
--drop-subclass Aphid:1              # 刪除來源子類（整張影像移除）
--split-subclass Thrips:1=Thrips_Damage   # 把來源子類拆成新的輸出類別
```

兩者都只需改動 `SOURCES` 的 `keep` 欄位與 `collect()` 的類別映射；`write_sample` 以下的流程不變。
建完後跑驗收：

```bash
.venv/Scripts/python.exe tools/verify_dataset_v5r.py
```

**Step 2 · Kaggle：訓練**

`Train Code/v9/train_ablation.ipynb`，只改第二個 cell 的 `ARM` / `EPOCHS` / `DATASET_SRC`。
新臂需先在 `Train Code/v9/v9_modules.py` 的 `ARMS` 表登錄（模組改完要 push，notebook 用 curl 從 GitHub raw 抓）。

**Step 3 · 本機：固定子集評估**

```bash
.venv/Scripts/python.exe tools/diag_localization.py --weights <該臂的 best.pt> --bootstrap 500
```

> 工具會自己從 `--data` 指到的 `data.yaml` 讀類別清單，並自動判斷哪些類別還需要 provenance 還原（看到 `Thrips_Damage` 就知道 Thrips 已拆類，不再嘗試還原）。拆類臂不需要改任何常數，但要記得加 `--data` 與 `--out` 指向新的資料集與輸出目錄。

**Step 4 · 判定**

套用 §3.1 的門檻，並把每臂的四個數字（中位 IoU × 2 子域 × 2 split）列成一張表。

### 3.4 驗收清單（每一臂都要過，缺一不可）

| # | 檢查 | 通過條件 | 不過代表 |
| ---: | --- | --- | --- |
| 1 | provenance 還原率（工具會印） | **100%** | 子域歸屬有誤，分層數字全部無效 |
| 2 | 本工具 8 類 AP50 vs `model.val()` | 差 < 0.03（Citrus_Leaf_Miner 除外） | 量測 pipeline 走鐘，見附錄 A |
| 3 | 固定子集的 `n_gt` | valid **299**、test **298** | 評估集被動到了，與基準不可比 |
| 4 | 若走續跑：`Transferred X/902` | **902/902** | 權重被 COCO 預訓練覆蓋，該場作廢 |
| 5 | `results.csv` 的 epoch 序列 | 無重疊列，或已依 `rows[:101] + rows[105:]` 拼接 | 平台期統計會取到錯的窗口 |

### 3.5 中止條件

| 條件 | 動作 |
| --- | --- |
| 標註者一致性中位 IoU < 0.85 | **停止 C3**，把天花板寫進報告限制章節。人工重標無法突破自己的一致性 |
| C1 與 C2 皆未達門檻 | **不要往 C3 投入**——重標是四臂裡唯一有人工成本的 |
| 任一臂讓 8 類等效 mAP50-95 掉超過 2σ（0.0077） | 回退該臂 |
| C0 與 A0 的差距超過 §3.1 門檻 | 停下來先擴充重複次數，否則所有結論不成立 |

## 附錄 A：量測過程中修掉的三個 bug

三個都會讓結論反向，也是 §3.4 驗收清單第 2 條存在的理由。

| # | bug | 症狀 | 修法 |
| ---: | --- | --- | --- |
| 1 | **EXIF 方向** | PIL 的 `.size` 回傳檔案原始長寬，ultralytics 走 cv2 讀圖會套用 EXIF 旋轉，兩者長寬相反 → Oily_Spot 的 recall 虛低 29 個百分點（0.667 vs 1.000），三個大框類別全部受害 | GT 的像素座標一律等推論拿到 `r.orig_shape` 之後再換算 |
| 2 | **多邊形標註** | 來源的 `Aphid_Leaf_Damage` 全是多邊形（13–41 欄），照 5 欄格式硬取前四個值 → 98 個框無法歸屬子域，且 `Aphid/Damage` 分層整個消失 | `parse_label()` 複製 `build_dataset_v5r.parse_label()` 的多邊形轉外接矩形 |
| 3 | **`[0,1]` 夾取** | `build_dataset_v5r.parse_label()` 會把溢出框夾進 `[0,1]`，provenance 比對若不複製同樣行為就對不上 → 63 個 Aphid 框未命中 | 加 `clip01()`，與建置腳本逐行一致 |

修完後 provenance 還原率由 80% 升到 **100%**（322/322、326/326）。
