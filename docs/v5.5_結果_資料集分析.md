## 0. 摘要

1. **九類**（新增 `Thrips_Damage` = id 8），`train 7,544 / valid 327 / test 326` 影像，
   `18,975 / 729 / 689` 框。
2. **全資料集跨 split 近重複配對為 0**（v5r 曾有 Thrips 48 組、Scale_Insect 46 組、
   Aphid 15 組）。做法是把近重複群組整群移進 train，**沒有刪除任何影像**。
3. **Scale_Insect 不再獨佔資料集**：v5r 的 raw pool 佔比 71.2% → v5.5 的 15.5%，
   `downsample_scale()` 特例因此移除，改走與其他類別相同的標準增強路徑。
4. **Canker 反而成為框數最多的類別**（train 6,509 框，佔 34.3%），每張圖 8.4 個框，
   76.9% 的框小於 32px——它接手了 v5r 時代 Scale_Insect 的「小框大戶」角色。
5. **兩個要注意的風險**：Thrips 的評估集偏小（valid 40 圖／84 框）且與 train 的
   中位框尺寸落差大（241 vs 112px）；Canker 與 Aphid 合計佔 train 框數 52.3%。
   兩者都會影響指標解讀，詳見 §4。

## 4. 兩個必須在解讀指標時一併考慮的風險

### 4.1 Thrips 的評估集偏小，且與 train 有分佈落差

| 類別 | 中位框尺寸 train / valid / test | 每圖框數 train / valid / test |
| --- | --- | --- |
| Oily_Spot | 394 / 372 / 385 | 1.0 / 1.0 / 1.0 |
| Canker | 22 / 22 / 22 | 8.4 / 7.0 / 7.6 |
| Sooty_Mold | 411 / 389 / 411 | 1.0 / 1.0 / 1.0 |
| Black_Spot | 373 / 352 / 361 | 1.0 / 1.0 / 1.0 |
| Scale_Insect | 28 / 24 / 23 | 4.8 / 5.3 / 3.4 |
| Citrus_Leaf_Miner | 172 / 221 / 175 | 1.5 / 1.1 / 1.2 |
| **Thrips** | **241 / 112 / 176** | 1.4 / 2.1 / 1.9 |
| Aphid | 157 / 144 / 135 | 2.8 / 2.9 / 2.8 |
| Thrips_Damage | 212 / 201 / 159 | 1.1 / 1.1 / 1.5 |

Thrips 的 train 中位框尺寸是 valid 的 2.2 倍。追查後是**兩個成因疊加**：

1. **去洩漏搬移的系統性影響（較小）**：被判定為近重複、整群移進 train 的 169 張
   Thrips 影像，中位框尺寸 247.0px；留在候選池的 385 張單張影像是 197.5px。
   移走的那批**系統性偏大約 25%**——因為連拍的田間照本來就傾向拍較大的目標。
2. **小樣本抽樣雜訊（主因）**：Thrips 類內尺寸跨度達 10.1x，而 valid 只有 84 個框。
   單張候選池的中位數是 197.5px，valid 抽到 112、test 抽到 176——test 接近母體，
   valid 是一次偏低的抽樣。

**影響**：Thrips 的 valid 指標會很不穩定，且 valid 與 test 之間的差異有相當部分來自
抽樣而非模型。**不要把 Thrips 的 valid/test 差異當成訊號**，判準應以 test 為主，
或把兩者合併看。這與 [P3 說明文件](archive/v9_說明_P3定位精度改善與測試流程.md) §3.1
對小 n 分層的既有警告一致，只是在 v5.5 上更嚴重。

### 4.2 類別不平衡的角色換人，但沒有消失

train 框數佔比：**Canker 34.3%**、Aphid 18.0%、Scale_Insect 20.5%，
三類合計 72.8%；四個大斑類別與 Citrus_Leaf_Miner 各只佔 4–5.5%。

v5r 時代是 Scale_Insect（27.8%）＋ Canker（27.9%）主導，v5.5 換成 Canker 獨大。
差別在於：**v5r 的 Scale_Insect 獨佔是被 `downsample_scale()` 人為壓過的結果**
（raw pool 原本佔 71.2%），而 v5.5 的 Canker 佔比是自然的——它每張圖就是有 8.4 個
病斑，不是取樣造成的。

**目前不建議對 Canker 做降採樣**：它的框雖多但集中在 772 張影像上，影像層級的
佔比（772/7,544 = 10.2%）與其他類別相當；框數多是病徵密度使然，不是重複取樣。
若後續發現 Canker 的高佔比在壓抑其他類別，再考慮調整 `cls` 損失權重而非動資料。
